# 生产切库记录：H2 → MySQL（2026-11-28）

> 环境：`120.24.204.138`（Ubuntu 24.04，1.6G 内存）
> 结论：**已切换完成**，8090 走 MySQL 8.0.46（`127.0.0.1:3308`），旧 H2 文件与 jar 全部保留可回滚。

## 做了什么

1. **安装 MySQL**：`apt-get install mysql-server` → 8.0.46；
   配置 `/etc/mysql/mysql.conf.d/zz-siyige.cnf`：
   ```ini
   [mysqld]
   port = 3308
   bind-address = 127.0.0.1
   innodb_buffer_pool_size = 128M
   performance_schema = OFF
   skip-log-bin
   ```
2. **建库建号**：库 `siyige`（utf8mb4/0900_ai_ci），账号 `siyige@127.0.0.1`；
   用 `schema-mysql-full.sql` 初始化，共 **42 张表**。
3. **数据迁移**（H2 文件库 → MySQL）：停服 → 复制 `/opt/siyige/data/siyige.mv.db` 到 `/tmp` →
   用一次性 Java 工具逐表 `TRUNCATE + 批量 INSERT`（H2 大写表名/列名统一转小写，CLOB/BLOB 转字符串/字节）：
   ```
   tables=42, total rows=27110
   sy_user 82 / sy_match 78 / sy_turn 643 / sy_post 2 / sy_event 25280 / sy_wallet_tx 263 …
   ```
4. **systemd 切换**（unit 备份：`/opt/siyige/siyige.service.bak-h2-1128`）：
   去掉 `--spring.datasource.url=jdbc:h2:file:...`，加 `--spring.profiles.active=mysql`，
   注入 `SIYIGE_DB_USER/PASSWORD` 环境变量；`After=mysql.service`。
5. **验证**：
   - 启动日志出现 `com.mysql.cj.jdbc.ConnectionImpl`；8090/8787 健康；
   - `predeploy_check.sh` 5 层全过；
   - 主链路自检 `verify_prod_full` **22/22**；
   - **持久化验证**：切库后注册的账号，`systemctl restart siyige` 之后仍能登录（证明写的是 MySQL 而非内存）。

## 回滚

```bash
cp /opt/siyige/siyige.service.bak-h2-1128 /etc/systemd/system/siyige.service
systemctl daemon-reload && systemctl restart siyige
```
H2 数据文件（`/opt/siyige/data/siyige.mv.db`，切库前快照）未改动；MySQL 期间的增量会丢失。

## 口径与注意

- 切库那一刻之后的数据只写 MySQL；H2 是切库前的快照，两边不再同步。
- MySQL 只监听 `127.0.0.1:3308`，不对公网开放；应用账号只有 `siyige` 库权限。
- 备份：`mysqldump -uroot --single-transaction siyige > /opt/siyige/backups/siyige-$(date +%F-%H%M).sql`
  （建议加进 crontab，保留最近 7 份；H2 时代的 `scripts/ops/backup.ps1` 只适用本地）。
- 单测仍跑 H2（`application-test.yml`），切库不影响 CI；`SchemaParityTest` 继续守着两套 schema 一致。
- 内存：Java 512M + MySQL 128M buffer，实测可用 690M；若再加服务先看 `free -m`。
