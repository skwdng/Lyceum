# 上线自检（每次部署后必须跑）

> 起因：2026-11-24 发现线上整体打不开 —— 服务器上 `/opt/lifekit/server.cjs` 在 11-23 的更新里
> 丢了「思弈阁反向代理」代码块，`/siyige/*` 全部 404。**只检查 `127.0.0.1:8090` 是查不出来的**，
> 必须从公网入口（8787）验证。

## 一条命令（在服务器上）

```bash
bash /opt/siyige/predeploy_check.sh
```

它按顺序检查：

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | `systemctl is-active siyige` | `active` |
| 2 | 应用自身 `127.0.0.1:8090/api/health` | `ok:true` |
| 3 | **公网入口** `127.0.0.1:8787/siyige/api/health` | `ok:true` |
| 4 | 静态页 `8787/siyige/v2/index.html` | 200 且 >500 字节 |
| 5 | 题库接口 `8787/siyige/api/topics` | 200 且 >500 字节 |
| 6 | lifekit 代理里是否还有 siyige 路由 | `grep proxyToSiyige` 命中 |

任何一条不过就打印原因并以非 0 退出。

## 如果第 3/4/5 条挂了（代理丢了）

```bash
python3 /tmp/fix_route.py          # 从 server.cjs.bak-* 里把 proxyToSiyige 块取回来
systemctl restart lifekit
```

脚本在仓库 `scripts/fix_lifekit_siyige_route.py`：幂等（已存在就跳过）、改前自动备份、
写完跑 `node --check` 语法检查。

## 前端链路自检（本地跑，需要 Chrome/Edge）

```bash
# 主链路 21 项：注册→开局→逐字→催一下→提示→语音按钮→草稿→提交→打完→复盘
node scripts/verify_prod_full.mjs 9870 http://120.24.204.138:8787/siyige

# 14 个页面冒烟：每个路由是否渲染出内容、有没有 JS 异常
node scripts/smoke_routes.mjs 9874 http://120.24.204.138:8787/siyige
```

两者都用 CDP 直连 headless 浏览器，返回非 0 表示有项没过。
