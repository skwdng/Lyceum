## 1. 通用约定

| 项 | 约定 |
|---|---|
| 传输 | `Authorization: Bearer <token>`；token 存前端 `localStorage['sy_jwt']` |
| 计时 | 过期时间 2 小时（`exp`），本期**不做 refresh token** |
| 错误体 | `{"code":"BAD_CREDENTIALS","message":"..."}`；`code` 机读、`message` 可读 |
| 密码 | 8–64 位，**必须同时含数字和字母**；Argon2id 哈希后落库，**从不存明文、不存 salt 列** |
| 账号 | 3–32 位字母 / 数字 / 下划线，**统一小写存储与比对**（不区分大小写） |
| 昵称 | 默认 = 账号；可在「我的」里改；发帖**不再**用请求体昵称覆盖 |
| 限流 | 同账号 5 次失败 / 5 分钟 → 锁 15 分钟；同 IP 20 次失败 / 5 分钟 → 锁 5 分钟 |

## 2. 五个接口

| # | 方法 路径 | 请求 | 成功 | 失败 |
|---|---|---|---|---|
| 1 | POST `/api/auth/register` | `{account, password}` | 200 `{token, user:{id,account,name}}` | 400 `INVALID_PARAM` / 409 `ACCOUNT_TAKEN` |
| 2 | POST `/api/auth/login` | `{account, password}` | 200 `{token, user:{id,account,name}}` | 401 `BAD_CREDENTIALS` / 429 `TOO_MANY_ATTEMPTS` / 503 `SERVICE_UNAVAILABLE` |
| 3 | POST `/api/auth/logout` | 头带 Bearer | 204 无 body | 401 `UNAUTHORIZED` / 503 `SERVICE_UNAVAILABLE` |
| 4 | GET `/api/auth/me` | 头带 Bearer | 200 `{id,account,name}` | 401 `UNAUTHORIZED` |
| 5 | PATCH `/api/auth/me` | `{name}` + 头带 Bearer | 200 `{id,account,name}` | 400 `INVALID_PARAM` / 401 `UNAUTHORIZED` |

**要点**
- 注册成功**直接返回 token**（不用再登录一次）。
- 登录/注册的响应里**永远没有** `password` / `passwordHash` / `status` 字段。
- `logout` 把 `jti` 写进 Redis 黑名单，TTL = token 剩余有效期；此后同一 token 一律 401。
- `PATCH /api/auth/me` 只改 `name`，**账号不可变**（账号是主键）。

## 3. 数据模型（增量，不改既有表结构）

`schema-auth.sql`（新建，只做 ALTER / CREATE INDEX，**不动 `schema.sql`**）：

```sql
alter table sy_user add column if not exists account       varchar(64);
alter table sy_user add column if not exists password_hash varchar(255);
alter table sy_user add column if not exists status        tinyint default 1;
create unique index if not exists ux_user_account on sy_user(account);
```

- `id` = 账号（小写）。`sy_user.id` 是 `varchar(32)`，账号规则 3–32 位正好放得下；
  历史 `u-demo` / `u-tester` 带连字符，与账号字符集天然隔离。
- `name` 是**昵称**列，`schema.sql` 里本来就有；社区帖子的作者昵称走
  `left join sy_user u on u.id = p.author_id` 取它，所以**改名立刻全站生效**，社区三表一行不用改。
- `password_hash` 存完整的 `$argon2id$v=19$m=19456,t=2,p=1$<salt>$<hash>`（约 95–120 字符）。
- 历史用户（`account IS NULL`）不可登录、不可认领，其帖子照常只读可见。

## 4. 错误码

| code | HTTP | 场景 |
|---|---|---|
| `INVALID_PARAM` | 400 | 账号格式 / 密码强度 / 昵称不合法、请求体不是合法 JSON |
| `ACCOUNT_TAKEN` | 409 | 注册时用户名已存在（含并发撞唯一索引） |
| `BAD_CREDENTIALS` | 401 | 用户名或密码错误；账号不存在、无密码、已禁用**都返回这一个** |
| `UNAUTHORIZED` | 401 | 未带 token / token 无效 / 已过期 / 已登出 |
| `TOO_MANY_ATTEMPTS` | 429 | 触发账号或 IP 失败次数限制 |
| `SERVICE_UNAVAILABLE` | 503 | Redis 不可用（登录限流、黑名单查询依赖它） |

## 5. 安全设计（实现约束，改代码前先读）

| 项 | 做法 |
|---|---|
| 哈希 | Argon2id，`new Argon2PasswordEncoder(16, 32, 1, 19456, 2)`（OWASP 2023 推荐档） |
| 盐 | 算法自带，随机生成并写进哈希串，**不建 salt 列** |
| 升级 | 登录成功且 `upgradeEncoding()` 为真 → 用新参数重算回写 |
| 防账号枚举 | 账号不存在 / 无密码 / 已禁用时**也跑一次哈希校验**（对假哈希），文案统一「用户名或密码错误」 |
| 日志 | 只打 `account`，**永不打印密码或哈希**；DTO 的 `toString()` 只含 account |
| JWT payload | 只有 `sub`（用户 id）/ `acc`（账号）/ `jti` / `iat` / `exp` 五项 |
| JWT 算法 | HS256；密钥取 `SIYIGE_JWT_SECRET`（≥32 字节），未配置时用内置开发密钥并打 WARN |
| 登出 | Redis `jwt:bl:{jti}`，TTL = 剩余有效期；**Redis 不可用 → 503，不放行**（fail-closed） |

## 6. 与社区接口的关系

社区 14 个接口的身份来源**从 `X-User-Id` 头改为 JWT 的 `sub`**，权限矩阵见
`社区接口契约.md` 的「权限矩阵」一节。摘要：

| 接口 | 未登录 | 已登录 |
|---|---|---|
| GET 列表 / 详情 / 评论 / 楼中楼 | 200（`liked` 恒 false） | 200 |
| POST `/posts/{id}/view` | 204，**不计数** | 204，计数 |
| 其余 POST / PATCH / DELETE | **401 `UNAUTHORIZED`** | 200 / 204 |

> `JwtAuthFilter` 只注册在 `/api/community/*`；`/api/auth/*` 不经过它（否则登录接口会被"需要登录"挡住）。

## 7. 本期决策记录（由 Lead 拍板，写进代码注释）

| # | 决策 | 理由 |
|---|---|---|
| A1 | **Redis 不可用 → 登录不可用（503）** | 限流与登出黑名单都依赖它；放开等于允许无限爆破、且登出失效 |
| A2 | **用户 id = 账号（小写）** | SPEC 对 user.id 无格式要求；varchar(32) 正好，且与历史 `u-*` 天然隔离 |
| A3 | **账号不区分大小写**（统一小写存储比对） | 防 `Zhang`/`zhang` 双开 |
| A4 | **历史 `u-demo` 等不认领、不可登录** | 它们是辩论/测试遗留身份，本期只把登录用在社区 |
| A5 | **401 后前端只弹登录框，不自动重试** | POST 重放有重复提交风险，让用户自己再点一次更可控 |
| A6 | 不做找回密码 / 邮箱验证 / 第三方登录 / RBAC | 本期范围只有社区 |
