# 评分有效性评测报告（SPEC §14.7）

> 这份报告回答一个问题：**「练了有用」凭什么这么说？**
> 五维分、能力雷达都是产品自己算的。如果没有外部基准校准，就是自己出卷子自己判卷。
> 这里用人工分档做基准，量化「系统评分与人判断的一致性」，并把「请第三方辩手独立标注」的流程做成了可执行的两步。

## 一、怎么跑

```bash
cd server
mvn test -Dtest=ScoreEvalTest        # 主体评测（断言阈值），附产物 target/eval-report.md
```

每次改提示词 / 改评分规则后必须跑一次：**这是「这次改动变好还是变坏」的判据**。

邀请辩手独立打分之后再跑：

```bash
python scripts/ingest_human_labels.py docs/评测集-盲评表.xlsx   # 生成 human-labels.json
cd server && mvn test -Dtest=ScoreHumanAlignTest                # 算 Spearman 与排序一致性
```

## 二、数据集

`server/src/test/resources/eval/score-dataset.json`

| 项 | 内容 |
|---|---|
| 规模 | **20 个辩题 × 4 档 = 80 条**（达到 SPEC 承诺的规模） |
| 分档 | 优秀 / 中等 / 较差 / 敷衍（各 20 条） |
| 标注口径 | 四维度人工判定：① 是否给判准 ② 是否给证据或机制 ③ 是否回应对方 ④ 是否以可核查的追问收尾 |
| 扩展方式 | 只加样本、不动代码 |

分档标准（写进 JSON 的 `rubric` 字段，便于别人复核标注）：

- **优秀**：有判断标准 + 有证据或具体机制 + 直接回应对方 + 以可核查的追问收尾
- **中等**：有立场和理由，但证据空泛、未真正回应对方
- **较差**：只有态度和形容词，无判准、无证据、无交锋
- **敷衍**：数字 / 单词 / 无信息量（生产链路上会被 `UtteranceCheck` 判为 EMPTY）

## 三、结果（2026-11-24，80 条）

```
与人排序一致性 pairwise accuracy = 120/120 = 1.000    （SPEC 要求 ≥0.75）
结构合法率                       100.0%              （SPEC 要求 ≥99%）
结构完整率                       100.0%              （SPEC 要求 ≥98%）
同一条重复评分最大漂移           0 分                 （SPEC 要求 ≤5）
同题内档位排序                   20/20 全部正确
```

各题分值分布（档3=优秀 … 档0=敷衍），20 题全部满足「优秀 > 中等 > 较差 > 敷衍」：

```
优秀档 59–70 · 中等档 42–49 · 较差档 38–43 · 敷衍档 0
```

## 四、这轮评测抓到的三个真问题（已修）

**① 敷衍发言拿了 43 分，和中等档撞在一起**

「对。」「11」「?」原来会走「基准分 + 各维度兜底」，拿到 43 分，与中等档（42–49）混在一起。
修法：`okTurns == 0 → total = 0`（全场没有一句有效内容就是 0 分）。

**② 口号式发言评分偏高**

「这就是应试教育的产物，很落后」「谁反对谁就是落后」「身体是革命的本钱」这类只有态度没有内容的句子，
靠 `应当/必须` 等判断词拿到了和「有观点但没证据」相近的分。
修法：新增 `SLOGAN` 模式（绝对化 + 无据无例）扣分，新增 `PRECISION` 模式（判准 / 口径 / 可核查 / 复核 / 指标）加分。

**③ 「判断词」本身不该给满分**

扩到 80 条后暴露：只写「必须限制」但完全没有理由的句子，和「应该限制，因为……」的中等档同分。
修法：判断词（我方认为/应当/必须）只有**同时出现理由**（因为/例如/据/口径）时才额外加分。

> 这三条都是「用外部基准一量就露馅」的典型，正好说明评测集不是形式主义。

## 五、邀请辩手独立标注（已备好工具）

作者自评只能证明「打分规则自洽」，**只有第三方辩手独立打分才能证明「贴近人的判断」**。为此做了：

| 文件 | 用途 |
|---|---|
| `docs/评测集-盲评表.xlsx` | 80 条样本**打乱顺序、隐藏档位与作者分**的盲评表，含「辩手A / 辩手B」两个独立工作表 + 评分口径说明页 |
| `scripts/ingest_human_labels.py` | 把填好的表汇总成 `human-labels.json`，并先算一遍「与作者基准的 Spearman」 |
| `server/src/test/java/.../ScoreHumanAlignTest.java` | 读汇总文件，断言与人工总分的 Spearman ≥0.6、排序一致性 ≥0.75；文件不存在时自动 skip（不阻塞 CI） |

**流程**：打印机/发文件 → 两位辩手各自填一列总分（互不参考）→ 回收 → 跑上面两条命令。

**链路已用模拟标注端到端验证过**（两位"辩手" = 作者分 ± 8/11 分噪声，仅用于证明流程跑得通）：

```
读到 80 条标注 · 标注者 ['A','B']
辩手A vs 作者基准：Spearman ρ = 0.959（n=80）
辩手B vs 作者基准：Spearman ρ = 0.952（n=80）
系统分 vs 人工分：Spearman ρ = 0.939 · pairwise accuracy = 0.855
```

> 这两行是**模拟数据**，只证明「回收 → 汇总 → 统计」不会卡住。真实数字要等辩手填完。

## 六、局限（必须说清楚）

1. **当前 80 条分档仍是作者本人标注**，不是两名辩手独立打分 —— 真实标注到位后，把 `humanScore`
   换成两人均分，报告里会多一列「与人分 Spearman」。
2. **只验证了「能不能区分优劣」**，还没验证「训练是否让人变强」。
   后者需要 A/B：同一批人（或脚本选手）训练前后对同一批题打分对比，样本量远大于 80。
3. 规则评分的上限就在这：它能稳定区分「有判准 + 有证据 + 有交锋」和「喊口号」，
   但分不清「论证巧妙但表述粗糙」和「表述漂亮但论证薄弱」—— 这一类要交给 AI 评审团。
