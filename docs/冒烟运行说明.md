# 冒烟运行说明（评分链路 · 单人局）

> 目标：一条命令验证「注册 → 开单人局 → 逐轮提交 → 复盘」整条链路是通的，并检查复盘里有
> `score.total` 与 `rubric`。不依赖浏览器、数据库客户端、LLM——只发 HTTP 请求。

相关文件：

| 文件 | 用途 |
|---|---|
| `scripts/e2e/smoke-solo-rubric.mjs` | 冒烟脚本（Node ESM，只用 `fetch`） |
| `server/src/test/java/com/siyige/eval/EvalHarnessTest.java` | 离线评测（pairwise / 单调性 / 漂移 / fabricated-quote / rubric 完整性），不起服务 |
| `server/target/eval-harness-report.md` | 评测脚手架自动生成的报告（跑完 EvalHarnessTest 后出现） |

---

## 一、起服务

前置：JDK 17、Maven 3.9+、Node 18+（冒烟脚本用到全局 `fetch`）。

```powershell
cd D:\siyige\server
mvn spring-boot:run
```

默认监听 `http://127.0.0.1:8080`，数据库是 H2 内存库，每次重启数据清空。
启动后另开一个终端确认：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/health
# ok  service
# --  ------
# True  siyige
```

> Redis 只影响社区模块。本机没起 Redis 时启动日志会打一条 ERROR，但评分链路照常工作。
> 想连本地 LLM 才需要 `siyige.llm.api-key`；不配 key 时 AI 走内置规则发言，冒烟完全可以离线跑。

## 二、跑冒烟

```powershell
cd D:\siyige
node scripts/e2e/smoke-solo-rubric.mjs
```

可配置环境变量（都有默认值，不配也能跑）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `BASE_URL` | `http://127.0.0.1:8080` | 服务地址；测试环境/端口改了用这个 |
| `STRICT_RUBRIC` | `0` | `1` = rubric 字段缺失就判失败（后端合并后再开） |
| `SMOKE_TIMEOUT_MS` | `180000` | 整场对局的最长等待时间 |
| `SMOKE_MODE` | `SPRINT` | 赛制；`SPRINT` 步数少，冒烟用；`FULL` 更接近真实 |
| `SMOKE_SEATS` | `B2` | 我方席位，逗号分隔 |

例子：

```powershell
$env:BASE_URL='http://127.0.0.1:8081'; node scripts/e2e/smoke-solo-rubric.mjs
$env:STRICT_RUBRIC='1'; node scripts/e2e/smoke-solo-rubric.mjs
```

## 三、预期输出

```
思弈阁冒烟 · BASE_URL=http://127.0.0.1:8080 · mode=SPRINT · seats=B2
[1/5] 健康检查 OK · service=siyige
[2/5] 注册 OK · account=smoke_1764228000123_456 · user=...
[3/5] 开局 OK · matchId=m... · topic=t1 ...
      第 1 次提交 · 立论 · step=1
      第 2 次提交 · 自由辩 · step=...
[4/5] 对局结束 · 提交 N 轮 · skip M 次 · status=FINISHED
[5/5] 复盘 OK · total=57 · matter=60 method=42 manner=58 adapt=40 evidence=45
[OK] rubric 存在 · version=v3-2026-11 · dims=5 · 权重合计=100 · focus=有

[PASS] 冒烟通过 · matchId=m... · total=57 · turns=... · rubric=有
```

- **退出码 0**：`total` 存在且在 0–100；rubric 存在，且能读出五维权重（合计 100）、focus。
- **退出码 1**：任何一步失败。失败会打印 `[FAIL] 步骤`、HTTP 状态码和**完整响应体**，
  直接贴给后端即可定位。
- rubric 已合并（`ScoreService.Rubric`，口径见 `docs/rubric-v3.md`）。如果跑的是旧构建、
  `score.rubric` 缺失，脚本默认只打 `[WARN]` 并以 0 退出（避免历史分支误红）；
  CI / 合并后验收请加 `STRICT_RUBRIC=1`，缺失或权重合计≠100 会直接失败。

## 四、常见失败与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `fetch failed` / `ECONNREFUSED` | 服务没起，或 `BASE_URL` 写错 | 先 `Invoke-RestMethod $BASE_URL/api/health`；确认端口 8080 |
| `/api/health` 返回 404 | 请求打到了前端静态站点（8080 之外） | 冒烟必须打后端端口 |
| 注册 400 `INVALID_PARAM` | 密码不满足策略（≥8 位且同时含数字与字母） | 脚本用 `Test123456`，改脚本时注意 |
| 开局 409/400 `余额不足` | 新用户赠送额度被用完后余额不够预扣 | 换新账号（脚本每次随机注册）；或重启服务重置内存库 |
| 提交 409 `NOT_YOUR_TURN` | 刚推进到下一步，仍按上一步状态提交 | 脚本会自动跳过并在下一轮重试；频繁出现说明轮询太密 |
| 对局一直 `RUNNING` 到超时 | AI 生成卡住 / 定时任务没跑 / 模型超时 | 看服务端日志；可调大 `SMOKE_TIMEOUT_MS`；不配 LLM key 时应走规则发言，很快 |
| `score.total` 缺失 | 复盘接口契约变了 | 按响应体检查 `review.score` 结构，先跑单测 `ScoreServiceTest` |
| `rubric 字段缺失` WARN | 跑的是 rubric 合并前的旧构建 | 重新 `mvn spring-boot:run`；合并后验收加 `STRICT_RUBRIC=1` |
| `rubric 完整性不通过` WARN | 五维权重和≠100 / 某维缺 basis / 缺 focus | 先跑 `-Dtest=ScoreRubricTest,EvalHarnessTest` 定位；`STRICT_RUBRIC=1` 下会直接失败 |
| 控制台中文乱码 | PowerShell 代码页 | `chcp 65001` 后再跑；文件本身是 UTF-8 |

## 五、只想跑离线评测（不起服务）

```powershell
cd D:\siyige
pwsh -File scripts/dev/locked-build.ps1 test -Dtest=EvalHarnessTest
```

若机器上没有 `pwsh`（只有 Windows PowerShell 5.1），用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev/locked-build.ps1 test "-Dtest=EvalHarnessTest"
```

> 注意：Windows PowerShell 5.1 下 `locked-build.ps1` 的 `$ErrorActionPreference='Stop'` 会把 Maven
> 子进程的 stderr（例如 JVM 的 CDS warning）当成终止错误，脚本可能提前退出、日志被截断。
> 遇到这种情况先看 `target/build-logs/mvn-test-*.log` 里有没有 `BUILD SUCCESS` / 测试统计，
> 或设置 `$env:JAVA_TOOL_OPTIONS='-Xshare:off'` 后再跑。

评测产出：

- 控制台：pairwise accuracy、档位均值、单调性违例、重复运行漂移、
  fabricated-quote 未命中率 / 真引用误判率、rubric 状态、8 条边界样例得分。
- 文件：`server/target/eval-harness-report.md`。

当前基线（2026-11-27，评分 v3 + QuoteGuard + rubric）：

```
pairwise accuracy        120/120 = 100.0%（目标 ≥75%）
档位均值                  good 64.8 / mid 45.9 / poor 39.7 / empty 0.0
重复运行漂移              0 分（3 次重跑，80 条）
fabricated-quote 未命中率 0/6 = 0.0%（QuoteGuard.inspect；真引用误判 0/3）
rubric                    五维 25/30/15/20/10，合计 100，basis/focus 全有
边界样例                  8 条全部 0–100，超时=0，最高分未超过优秀档均值 +5
```

## 六、冒烟覆盖不到的部分

- 真实 LLM 输出质量（冒烟只验证链路；质量看 `EvalHarnessTest` 的指标）。
- 支付回调、多人房间、SSE 推送、管理端。
- rubric 的**内容正确性**——冒烟只做结构校验（字段存在、权重合计、basis/focus 非空）；
  权重是否合理、basis 是否和真实命中对得上，由 `ScoreRubricTest` 与 `EvalHarnessTest` 的
  rubric 完整性用例校验。
