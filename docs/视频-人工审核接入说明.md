# 视频模块 · 人工审核接入说明

> 状态：**人工审核台默认关闭**，等管理端（`dev-wandou23333-feature-admin`）合并后再接。
> 机器初审已经全量生效，不受影响。

## 现在是什么状态

| 能力 | 状态 |
|---|---|
| 机器初审（结构 / 违禁词 / 风险词） | ✅ 已生效 |
| 审核留痕（`sy_video_audit`） | ✅ 已生效，每次判定都写 |
| 待复核视频**不上广场** | ✅ 已生效 |
| 人工复核台（通过/驳回/恢复） | 🔒 已实现但**关闭** |

关闭方式是配置项：

```yaml
siyige:
  video:
    audit:
      console-enabled: false     # true 才开放审核台
```

关闭时：

- 前端不显示「审核台」按钮（读 `/api/video/audit/rules` 的 `consoleEnabled`）
- 直接调接口也挡掉：

```
GET  /api/video/audit/queue      → 409 人工审核台暂未开放（等待管理端接入）
GET  /api/video/audit/{id}/logs  → 409 同上
POST /api/video/audit/{id}/decide → 409 同上
POST /api/video/audit/{id}/restore → 409 同上
```

**为什么默认关**：现在只校验「已登录」，任何注册用户都能给自己过审。这不是权限问题，是安全问题。

## 管理端合并后怎么接（三步）

### 1. 换成管理员校验

`VideoController` 里只有一个开关方法：

```java
private void requireConsole() {
    if (!consoleEnabled)
        throw new IllegalStateException("人工审核台暂未开放（等待管理端接入）");
}
```

改成用他的管理员认证：

```java
private void requireConsole() {
    if (!AdminContext.isAdmin())          // ← 用他的 admin 包
        throw new AuthException("FORBIDDEN", "需要管理员权限");
}
```

四个接口里的 `requireConsole()` 调用不用动。

### 2. 前端入口挪到管理端

现在视频模块里的 `vOpenAudit()` / `vQueue()` / `vDecide()` / `vRestore()` 是完整实现，
管理端只要：

- 复制这四个函数的渲染（或直接 `import` 后复用）
- 把按钮放进管理端页面，按管理员身份显示

**不需要重写业务逻辑**，接口路径和返回结构都是稳定的。

### 3. 审核结果落到同一张表

`sy_video_audit` 的字段已经和管理端的审计日志同构：

| 字段 | 含义 | 与 admin 侧对应 |
|---|---|---|
| `stage` | MACHINE / HUMAN | 操作者类型 |
| `result` | PASS / REVIEW / REJECT / RESTORE | 动作 |
| `reason` | 判定依据 | 处理记录里的理由 |
| `operator` | 机器 / 管理员 id | 操作人 |
| `prev_status` | 判定前状态 | 一键恢复用 |
| `restored` | 是否已被撤销 | 恢复标记 |

**合并时可以把这两张表（`sy_video_audit` 与 `sy_admin_audit`）统一成一张**，
或者保留两张、管理端页面同时展示——看他 admin 分支的实际表结构再定。
