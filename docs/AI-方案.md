# 思弈阁 · AI 层方案（2026-11-01）

> 面向问题：AI 席位现在只会「随机抽模板」，不接队友的话，协同分永远是 0。
> 本文给出四层结构、落地顺序、成本预算与可判定的验收标准。

| # | 现象 | 证据 |
|---|---|---|
| 1 | AI 不接队友的话 | 12 步全程无人引用上一位队友，发言彼此独立 |

## 1. 四层结构

```
人设层 Personas ──┐
上下文层 Context ──┼─→ 生成 Generate ─→ 护栏 Guard ─→ 评分 Score
（8 席差异化）    （摘要+最近发言）（模型/模板）  （去AI味/承接/长度）（可解释）
```

### 1.1 人设层（`ai/Personas.java`）

8 个席位各有人设：姓名、风格、语气、字数区间、说话习惯。

| 席位 | 人设 | 风格 | 习惯 |
|---|---|---|---|
| A1 | 沈亦舟 | 硬框架 | 开场必给判断标准 |
| A2 | 苏晚 | 快攻 | 抓一句话连环反问 |
| A3 | 梁未 | 守中转 | 用具体场景落地 |
| A4 | 许晏清 | 收束 | 结辩把分歧归成两三条 |
| B1 | 何书言 | 慢热 | 先重定义关键词 |
| B2 | 路知远 | 举例型 | 「对方那个例子恰好说明」 |
| B3 | 陆见微 | 定义控 | 抓偷换概念，要求统一口径 |
| B4 | 周砚 | 反打 | 「对方从头到尾没回答一个问题」 |

**为什么要人设**：4v4 里 7 个 AI 是同一模型同一提示词，出来必然像一个人。人设是唯一低成本的差异化手段。

### 1.2 上下文层（`AiService.buildPrompt`）

不塞全场，只塞四样——**这就是成本控制的全部**：

1. 【我方已说过】同侧最近 2 条（40–60 字摘要）→ 防止重复自己
2. 【同侧队友刚才说】同侧最近一条（90 字）→ 必须承接
3. 【对方最近说】对方最近一条（90 字）→ 必须回应
4. 【当前环节】立论/驳立论/质询/自由辩/总结 → 决定语体

**不做的事**：不做全场摘要（成本高、且模型对长文本的承接反而更差）。

### 1.3 生成层

```java
// 有 key：走模型
llm.chat(SYSTEM, buildPrompt(...), temperature=0.85, timeout=25s)
// 无 key / 失败：模板兜底，但兜底也必须接话
template(seat, seg, mateLast, history)
```

温度 0.85：辩论需要锐度，太低会变成车轱辘话。

### 1.4 护栏层（`AiService.guard`）

| 规则 | 做法 |
|---|---|
| 去 AI 味 | 正则删「作为AI」「我是一个语言模型」 |
| 承接检查 | 若队友有发言但输出无承接语 → 自动补一句「顺着我方X辩说的『hook』…」 |
| 长度 | 超出人设上限则在最后一个句号处截断 |
| 引用去重 | 同一句 hook 被引用过就不再引用，防止全员复读 |

### 1.5 评分层（`ScoreService`，本轮新增）

协同分 = 真的去测「有没有接住」：

| 判定 | 分值 |
|---|---|
| 原样引用队友 6 字以上片段（`sharesPhrase`） | +3 |
| 4-gram 重叠率 ≥ 8% | +3 |
| 只用衔接语但没复用论点 | +2 |
| 与上一轮自己重复 > 60% | −2 |
| 上限 | 12 分，直接计入总分（封顶 100） |

## 3. 成本与延迟预算

以 deepseek-chat 为例（按 2026-11 公开价量级估算）：

| 项 | 量 |
|---|---|
| 单次 AI 发言 | 输入 ~300 tok（系统+上下文）、输出 ~200 tok |
| 一场 12 步的 AI 调用 | 6–9 次（取决于你占几个席位） |
| 单场 token 合计 | 约 5–6k |
| 单场成本 | 约 ¥0.01 |
| 100 场 | 约 ¥1 |

延迟：输入 300 tok 时首字 0.8–1.5s，整段 3–6s。**必须配「AI 思考中」的占位动画**，否则用户以为卡死。

| # | 指标 | 阈值 | 怎么测 |

## 8. P1 落地：论据库（2026-11-01 已上线）

### 8.1 它解决什么

原来的问题：AI 和玩家都在说「以试点地区为例」这种没有依据的空话，评分函数只能数关键词（数据/研究/报告），**数不出来就是 0**，也无法区分"真引用"和"编一个数字"。

论据库把这件事变成**可判定**的：

| 行为 | 判定 | 分值 |
|---|---|---|
| 引用论据卡里的内容（≥8 字重合）或出处 | cited +1 | 每条约 +9 |
| 出现卡里没有的数字（37%、21% 这类） | fabricated +1 | 每条 −8，并点名 |
| 两者都没有 | 维持基础分 | 40 起 |

### 8.2 数据（48 张，12 题 × 4 张）

表 sy_evidence：id / topic_id / side(A正 B反 C双方) / claim / source / pub_year / verified / tags

**诚实原则（重要）**：

- claim 只写「制度事实」或「可核查的口径」，**不写具体统计数字**——数字最容易编，也最容易过时
- erified=true 表示出处是可查的公开法规/文件；alse 在 UI 上标「需核实」，AI 引用时也会带上「（待核实）」
- 这不是缺陷，是产品立场：**教用户对来源保持怀疑**，比给一个看起来权威的假数字更有价值

### 8.3 三方怎么用

| 角色 | 用法 |
|---|---|
| AI | 提示词注入本方 + 中立卡片（最多 4 条），规则里写死「只能用这些，引用时写出处，不许编数字」 |
| 玩家 | 对局右侧「论据卡」面板，点一下插入「说法（据出处）」到发言框 |
| 评分 | 复盘页显示「引用 N 条 / 编造 M 处（具体数字）」，写进总分 |

### 8.4 实测

`
输入：我方引一条制度事实：课程考核合格方可获得学分…（据《普通高等学校学生管理规定》）
输入：据某平台统计，取消期末后学生平均分提升了 37%，不及格率下降了 21%

结果：论据分 34 · 引用 1 条 · 编造 2 处 ['37%', '21%']
问题：发言里出现了论据库里查不到的数字：37%、21%。辩论里编数字是最伤可信度的失分点。
`

AI 侧现在会这样说话（同一场的真实输出）：

> 制度上就不强制一次性闭卷考试，据《普通高等学校学生管理规定》（教育部令第41号，2017），课程考核合格即获学分，形式由学校规定。
> …替代方案能否成立，取决于复核主体与申诉通道是否明确，据《深化新时代教育评价改革总体方案》（2020·待核实）的要求…

### 8.5 已知局限

1. 卡片是「口径型」，不是「数据型」——想要真实统计数据，需要人工核实后逐条录入并置 erified=true
2. 6–8 字的重合判定会有误报（正常复述也可能命中），阈值可调
3. 编造检测只认「数字+单位」，编造机构名/年份抓不到
