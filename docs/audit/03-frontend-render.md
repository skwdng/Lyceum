# 03 · 前端审计：对局页渲染 / 发言顺序 / 「催一下」UI

> 对象：`web/src/views/MatchView.vue`、`web/src/stores/debate.js`、`debate.css`。
> 方法：**代码级审计（确定项）+ 时序推算 + 探针尝试**。探针第一轮没拿到有效会话（`matchId=null`、`typedBefore.typed is not iterable`），
> 有效实测只有 375px 视口（`scrollWidth=375`，无横向溢出）与既有 63 项复盘页断言；
> 因此本文每条都标注「确定 / 待实测」，**不把推算当实测**。

---

## 0. 结论

前端没有「把顺序打乱」的独立 bug——它的问题全部来自**用一个串行播放器去追一个更快的生产者**：

- 打字机一条 ≈ 6.5–9.7s，AI 接话间隔 3.0–7.5s → 数据永远先到，播放永远排队；
- 为了不让「未来的发言」提前泄题，列表把「第一条未打完之后的全部发言」隐藏（`firstUntyped`）——
  于是队列一长，用户看到的就是「上一句消失 / 这一段没出现」；
- 刷新/重进会重置播放进度，整场从头再打一遍。

这三点与 02 §⑤ 的节奏对账（17 轮累计积压 ≈60s）是同一件事的两端。

## 2. 与「发言顺序」的关系（澄清）

- `turnsView` 的排序键是 `(step, SEAT_ORDER[seat])`，**顺序本身稳定**；探针拿不到会话，但代码层面没有「乱序」来源。
- 用户感知的「顺序乱」有两种真来源，都不在前端排序：
  1. 后端同一步写了两条（01 §2 #1/#2）→ 前端按 (step,seat) 去重，**后到的覆盖先到的**，于是「我说的话变成了 AI 的」或反之；
  2. 后端抢拍把席位换成别人（01 §2 #4、04 F2）→ 气泡挂在错误席位下，看起来就是「顺序错了」。
- 所以 B4 只修播放；**顺序问题必须在 B1/B2 修后端**。

## 3. 复验方式（B4 修完后）

```powershell
# 起服务后，用无头 Edge + CDP，采样三条：
# 1) 连续 3 条 AI 发言的 DOM 文本长度序列：必须单调增、无回退、同一时刻只有一条在增长
# 2) 气泡 (step,seat) 序列 == 接口 turns 序列（去重后）
# 3) 催一下：连点 3 次，按钮只消失一次；AI 生成中点一次，必须出现「正在组织语言」提示
```
