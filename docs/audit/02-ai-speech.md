## 1. 必答问题

### ① 截断是否切在句中 / 引号内？segChars 与 segCharCap 是否双重截断？

**结论：是，而且是"三处字数来源各说各话"导致的确定性截断。**

| 来源 | 位置 | 立论（A1）取值 | 作用 |
|---|---|---|---|
| `segChars(seg,p)` | `AiService.java:728-738` | `220–320` | prompt 里【本轮要求】1「输出 X 字」 |
| `Format.segCharCap(seg,duty)` | `Format.java:50-59` | `260` | prompt 里【字数】上限 + 护栏硬上限 |
| `Persona.maxChars()` | `Personas.java:33` | `260` | 护栏硬上限（与上一行取 min） |

- 同一段 prompt 里同时写着「最多 260 字」（`:622-623`）和「输出 220–320 字」（`:668`）——**模型按 320 写，护栏按 260 切**。
- 切法（`AiService.java:914-917`）：先找 `cap` 之前最后一个「。」；找不到（模型写了一句无句读长句，很常见）→ 直接 `substring(0, cap) + '。'`，**切在词中间**。
- 引号内的截断：截在 `「…」` 中间会留下孤立 `「`，`QuoteGuard.dropDanglingOpeners()`（`QuoteGuard.java:306-319`）事后把开引号删掉 → 结果是"半句 + 引号残缺"。
- 真实上限还要更小：`min(Persona.maxChars, segCharCap)`。例：A2 质询·答 = `min(190, 120) = 120`。

夹具：`立论的字数指令自相矛盾_护栏按260硬切`、`无句号时截断切在词中间`（320 字零句读 → 输出恒为 261 字，切口前无任何句读）。

### ② cutRepeats 会误杀正常承接结构吗？

**结论：会，两个典型样例。** 判据是「同一句 ≥8 字第二次出现 → `break`，后面全丢」（`AiService.java:991-1023`），它无法区分"模型退化复读"与"结辩式复现/质询式重复追问"。

样例 1（结辩，`cutRepeats误杀结辩的复现句`）：

```
我方判准只有一条：可执行、可监督、可追责。          ← 开场立
第一，标准可查：对方至今没有给出一个能被第三方复核的口径。
第二，过程可看：执行主体是谁，对方从立论回避到结辩。
第三，结果可追：出了事追到机构还是个人，对方始终没有回答。
我方判准只有一条：可执行、可监督、可追责。          ← 收尾再点一遍（修辞，不是退化）
所以请评委按这三条打分，谢谢。                      ← 被砍掉
```

样例 2（质询，`cutRepeats误杀质询的重复追问`）：`请对方正面回答：谁执行、谁复核、谁追责。` 夹在三条论证之间出现三次 → 第二次出现即截断，`我方收在这个问题上` 丢失。

危害：**丢的恰好是"收束句/收束段"**——结辩的裁判指令、质询的最后一句追问，都是结构上最重要的位置。

### ③ QuoteGuard 的 8 字门槛 / Dice 0.80 在短引文上的表现？出处豁免会放过编造数据吗？

**结论：两个方向的错都有——长引文太松（放过语义反转），短引文太严（误杀忠实缩略）；出处豁免是个后门。**

| 场景 | 引文（归一化字数） | 相似度 | 判定 | 对不对 |
|---|---|---|---|---|
| 原文「必须有刚性凭证」，引文改成「**必须没有**刚性凭证」 | 17 | **0.90** | MATCHED | ❌ 语义相反却放行 |
| 原文「取消**期末考试**会让…**彻底**放弃复习」，引文缩略成「取消期末会让学生放弃复习」 | 12 | 0.69 | FABRICATED → 改写 | ❌ 忠实缩略被判编造 |
| 引文 8 字、改 1 个字 | 8 | ≈0.66–0.71 | FABRICATED | ⚠ 8 字区间等于"必须逐字" |
| 引文裹书名号：「《中国教育发展报告》显示…下降 37%」 | 13 | — | **CITATION（免检）** | ❌ 编造数据穿过护栏 |
| 引文前置「据」：`据「2021 年中国教育发展报告」，不及格率下降 37%` | 12 | — | **CITATION（免检）** | ❌ 同上 |

- Dice 用窗口二元组（`QuoteGuard.java:221-256`），**对否定词/数量词的增删不敏感**：17 字里插一个「没」，只毁 2–3 个 bigram，相似度仍 >0.9。
- 8 字门槛（`MIN_QUOTE_CHARS=8`, `QuoteGuard.java:39`）意味着 8–11 字的引文只有 ≤1 个 bigram 的容错空间 → 忠实缩略被判编造后会被改写成「那个说法」，引述感直接丢失。
- 出处豁免（`looksLikeCitation`, `QuoteGuard.java:183-196`）对**整条引文**免检，只看引文里有没有书名号或前面 6 字里有没有「据/根据/依据/出自/来源/援引」。这正好覆盖了产品最怕的一类输出：**带出处的假数字**。评分侧（`ScoreService` 的数字检测）另有一套，但**发言正文已经带着这个假数字发给用户了**。

### ④ 无 key / 429 / 超时 / 预算耗尽，四条路径用户看到什么？重试 3 次失败后 step 会卡死吗？

**用户看到的完全一样：一个正常气泡 + 一个「离线草稿」标签。**

| 路径 | AiService 内部 | 用户可见 | 问题 |
|---|---|---|---|
| 无 key（`llmEnabled()=false`） | 直接模板，`analysisStatus=none` | 模板句 + 「离线草稿」 | 演示态被标成"离线"，像故障 |
| 429 / 5xx（`LlmClient.post` 抛 `LLM HTTP 429`） | catch → 模板，`degraded=true` | 同上 | 无重试、无退避 |
| 超时（25s，`chat(...,25)`） | catch → 模板 | 同上 | 25s 里页面只有打字机在转 |
| 预算耗尽（≥40000） | 不分析、模板，`analysisStatus=budget-exhausted` | 同上 | 用户不知道剩余额度、不知道何时恢复 |

- 落库只有**一个布尔**：`sp.degraded() ? "TEMPLATE" : "OK"`（`MatchService.java:385`）。`analysisStatus` 虽然已经能区分原因（`AiService.java:440/511`），但**没有任何一层把它落库或推到前端** → 复盘页、运营看板都分不清"模型挂了"和"预算烧穿"。
- 前端标签：`debate.js:254` 把 `status === 'TEMPLATE'` 映射成 `degraded`，`MatchView.vue:556` 渲染成 `离线草稿`，title 写「模板降级或本地离线草稿，**不计入正式评分**」。无 key 模式下 **7 个 AI 席位每一条都挂这个标签**，而它并不是"离线"，也不是"用户草稿"。
- **不会卡死**：`speakForSolo*` 内部把模型异常全吃了，永远返回一段文本 → `advance()` 一定执行，下一步照常推进。
- 但「重试 3 次」这层保护（`MatchService.java:357-365`）**对模型失败完全不生效**——它只在 `aiLine` 抛异常时才累加计数，而模型失败已被 AiService 吞掉。真正能触发 `tries>3` 的只有 `store`/`advance` 类异常，那时走 `finishMatch(id,"ABANDONED")`，**并且不发 `match.end` / 不发任何失败事件**（`:363`）→ 前端只能等轮询发现对局没了。`catch` 分支（`:402-407`）也只 log，无 SSE 通知。
- 重复插入已被 `store.hasTurn()` + `generating` 集合挡住（`:382-386`、`:353`），**不会一步多句**——这一条是好的。

### ⑤ 节奏算例：aiThinkMs(700) + aiGap 3500+2500jitter 与打字机 per=clamp(6500/字数,18,150) 会不会"下句在上一句没打完时到达"？

**结论：会，而且是常态；`ai-think-ms: 700` 是个死配置，对节奏零影响。**

先修一个前提：`MatchService.thinkMs()`（`:908`）**没有任何调用方**（夹具 `aiThinkMs配置从未被使用` 直接扫源码：`thinkMs()` 全文只出现 1 次，就是定义本身；`application.yml` 里 `ai-think-ms: 700` 永远不会被读）。真实接话间隔由 `aiDeadline()`（`:528-540`）决定：

| 席位 | 间隔公式 | 区间 |
|---|---|---|
| A2 / B2（快攻派 ×0.85） | `(3500 + rand(0,2500)) × 0.85` | **2975 – 5100 ms** |
| A1 / A4 / B1 / B3（×1.0） | `3500 + rand(0,2500)` | **3500 – 6000 ms** |
| A3 / B4（×1.25） | `× 1.25` | **4375 – 7500 ms** |

打字机（`debate.js:641-646`）总时长 ≈「6500ms 打完整段」+ 标点额外停顿（句末 `per×8` 封顶 520ms、逗号 `per×3` 封顶 240ms），**基本与字数无关**：

| 样例（本场真实长度） | 字数 | per | 打字总时长 |
|---|---|---|---|
| 自由辩短打 | 90 | 72ms | **8544 ms** |
| 结辩 | 137 | 47ms | **9682 ms** |
| 立论（护栏上限） | 260 | 25ms | ≈ 8200 ms |

对账：打字 8.2–9.7s vs 接话 3.0–7.5s → **每一条 AI 发言都早于上一条打完到达**（只有 A3/B4 的极端慢档 7500ms 勉强接近）。前端是**串行打字**（`debate.js:624-626`，只推进最靠前的一条），所以不会乱序，但会**稳定积压**：17 个 AI 轮（18 步 − 我占的 1 步）× 平均积压（8.5s − 4.75s ≈ 3.7s）≈ **60s** 的累计滞后。

体感后果：轮到我发言时，上一条 AI 的话可能还在打；「下句压上句」在数据层已落库（前端只是排队播），中途刷新/结束会一次性补齐（`debate.js:417`、`:845`）——所以不算卡死，但**对话节奏和真实辩论对不上**。

### ⑥ 质询问/答与结辩有没有用对应 Persona？

**生成层：用了，而且 8 席差异是真的进的 prompt。** `buildPrompt`（`AiService.java:601-603` 身份/人设 + `:609-621` duty 硬性要求）把 `style/tone/habit/strategy` 写进【身份】【你的推理方式】，`temperature` 与 `minChars/maxChars` 也按席位取。

| 环节 | 席位 | 人设是否进 prompt | 与环节指令是否自洽 |
|---|---|---|---|
| 立论 | A1 / B1 | ✅ | ✅（判准 vs 定义，都是立论动作） |
| 驳立论 | A2 / B2 | ✅ | ✅ |
| 质询·问 | A3 / B3 | ✅ | ⚠ A3 人设「先给一个具体场景再归纳」与「以问句为主、不要长篇论证」冲突 |
| 质询·答 | B3 / A3 | ✅ | ❌ prompt 里同时有「以问句为主/不要长篇论证」和「第一句必须**正面回答**」——互斥（夹具 `质询答的prompt同时要求全问句和先正面回答`） |
| 总结 | B4 / A4 | ✅ | ✅ A4「三个分歧收一下」与「把全场分歧归成 2–3 条」同向（夹具 `结辩席位人设生效且不冲突`） |
| 兜底模板 | 全部 | ❌ **完全不看人设与 duty** | 见下 |

两个空洞：
1. `template()`（`:741-751`）的键只有 `side + seg`，**不认识 duty 也不认识席位** → 质询·答 抽到的仍是提问句（夹具 `质询答的兜底模板仍然是提问句`：12 次抽样全部以问号结尾，第一句没有正面回答）。
2. 无 key 模式下 8 席只剩 **10 个池（2 侧 × 5 环节）**：同侧 4 个席位共用同一池、只是随机去重 ≠ 人设差异 → **"8 席人设"这个卖点在无 key 时基本不存在**（`AI-方案.md` §1.1 与 §5 的实测样例是接了 key 的）。
