# 项目进度 · Lyceum 思弈阁

## 一句话

**Lyceum（思弈阁）是一个 AI 4v4 辩论训练系统**：8 个 AI 辩手各占一个席位、各有自己的辩论风格与推理策略，用户在其中一个席位上和整支队伍对辩，系统按真实赛制推进 12 个环节，结束后给出五维评分与逐回合点评。

在线试用：<http://120.24.204.138:8787/siyige/>

---

## 现在能做什么（已完成）

### 对辩主流程
- [x] 标准 12 步赛制：立论 → 驳立论 → 质询 → 自由辩 → 总结
- [x] 8 个 AI 席位，每个席位独立人设（风格 / 温度 / 思考时长 / 推理策略）
- [x] 席位自选：任意挑一个位置，其余 7 席由 AI 补位
- [x] 自拟辩题 + AI 可辩性审核（不合格会给出修改建议）
- [x] 自由辩抢拍：8 秒窗口，抢到才拿到话筒
- [x] 抓漏玩法：AI 每轮埋一个逻辑漏洞，玩家从 5 类里指认，正确 +3
- [x] 每步限时 + 打字自动续时（单人模式不限时）

### 节奏与体验
- [x] 打字机输出：逐字出现，句号处停顿，严格串行（上一个人说完，下一个才开口）
- [x] AI 回应间隔 10–15 秒，模拟真人思考
- [x] 单人模式「催一下」：不想等就让它立刻接话
- [x] 手机端适配：底部导航、输入框吸底、单列布局

### 复盘与数据
- [x] 五维评分：立论 / 论证 / 表达 / 应变 / 论据，加权总分
- [x] 逐回合点评 + 可采纳的改写建议
- [x] 论据卡库：48 张卡片（12 辩题 × 4），标注「已核实 / 需核实」
- [x] 作战卡（赛前材料）：定义、立论骨架、对方可能打法、回应句式
- [x] 热辩榜：Redis ZSET 实时排序
- [x] 能力诊断：五维滑动平均 + 雷达图
- [x] 辩论记录：只记录不排名（刻意不做段位）

### 多人
- [x] 8 席房间：建房 / 房间号加入 / 准备 / 开局
- [x] 房间内席位分配与缺位 AI 补位

### 社区（已完成，2026-11-02 并入 SPA）
- [x] 帖子：闲聊 / 教程 / 求助三类，Markdown 正文，可关联辩题
- [x] 列表筛选与排序：类型 / 标题 / 关联辩题 / 日期，四种排序（最新 / 最多评论 / 最多点赞 / 最热）
- [x] 两层楼中楼：楼 + 楼中楼，回复对象精确到人（「A 回复了 B」），无第三层
- [x] 点赞：帖子与评论都支持，幂等、可取消，不影响任何评分排名
- [x] 浏览数：Redis 自然日去重 + 增量合并回写，读时叠加（即时可见）
- [x] 敏感词打码：命中后全角＊替换后落库，不拒稿
- [x] 帖子搜索：标题模糊匹配（按规范只搜标题，不搜正文）
- [x] 自检：27 项接口冒烟 + 浏览器端 14 项 UI 自检

### 账号与登录（已完成，2026-11-03）
- [x] 注册 / 登录 / 登出，账号为用户名
- [x] 密码 Argon2id 哈希（m=19MiB, t=2, p=1），算法自带盐，不存明文
- [x] 会话 JWT（HS256，2 小时），登出写 Redis 黑名单即时失效
- [x] 登录失败限流（账号 5 次 / IP 20 次，触发后锁定）
- [x] 社区改为登录制：发帖 / 评论 / 点赞要登录，浏览不用；未登录浏览不计数
- [x] 昵称：注册时默认等于用户名，「我的」里可改，改名全站即时生效
- [x] 账号入口收进侧栏左下角，手机端底栏保留入口

### 社区治理与账号安全（已完成，2026-11-03）
- [x] 举报：帖子 / 评论可举报，四种原因 + 补充说明（过敏感词打码），同一人同一目标只能举报一次
- [x] 举报队列：按被举报目标聚合，按举报人数降序，≥3 人标「多人举报」，不自动隐藏内容
- [x] 处置三选一：忽略 / 删除内容（软删）/ 社区禁言 1·3·7 天，可组合
- [x] 独立管理员体系：`sy_admin` 表 + 独立 JWT，与普通用户完全隔离，互相不认对方的令牌
- [x] 管理后台：`/admin` 独立页面，举报队列 / 用户管理 / 处理记录三个 tab
- [x] 两种处罚互不干扰：社区禁言有期限（到期自动解）、全站封禁走 `sy_user.status`（立即生效）
- [x] 处理记录 + 一键恢复：恢复被删内容、记录标记「已恢复」、关联举报转 REOPENED
- [x] 改密码：用户端「我的」与管理端均可改；改后所有旧令牌立即失效（`TOKEN_STALE`）
- [x] 自检：289 个单测 + 举报/管理员冒烟 16 项 + 改密/恢复冒烟 22 项 + 4 套浏览器自检

## 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Java 17 · Spring Boot 3.3 · JdbcTemplate · SSE |
| 数据库 | H2（内存/文件），Redis（热榜 + 社区） |
| 前端 | 原生 JS，按模块拆分（无框架、无构建步骤） |
| 大模型 | DeepSeek（OpenAI 兼容接口） |
| 部署 | 阿里云 2C1G · systemd · Nginx 反代 |

### 代码结构

```
server/src/main/java/com/siyige/
├── api/          接口层
├── service/      赛制引擎、评分、复盘
├── ai/           AI 辩手（人设、提示词、生成）
├── community/    社区模块（独立包，合作方负责）
├── auth/         登录模块（注册 / JWT / 过滤器 / 限流 / 改密）
├── admin/        管理后台（独立账号体系 / 举报处置 / 处理记录与恢复）
├── repo/         数据访问
└── engine/       赛制定义

server/src/main/resources/static/
├── index.html    空壳
├── admin.html    管理后台（独立页，不加载 core.js）
├── css/app.css   样式
└── js/
    ├── core.js   全局状态、请求、路由
    ├── admin.js  管理后台逻辑（独立，不依赖 core.js）
    └── views/    一人一块：solo / match / review / hot / diag / records / room / community / auth
```
