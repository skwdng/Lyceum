# 辩论接口鉴权契约（v1.0 · 2026-11-04）

> **范围**：`/api/matches/**`、`/api/records`、`/api/diag`、`/api/rooms/**` 的登录与归属规则。
> **上游方案**：`D:\siyige-v2\辩论侧接入账号-修改方案.md`（决策 A 路线：未登录不能玩）。
> **账号体系本身**见 `docs/认证接口契约.md`；社区侧见 `docs/社区接口契约.md`。

---

## 1. 一句话规则

**辩题 / 热榜 / 赛制 / 健康检查保持匿名可访问；其余辩论接口一律要登录，
且对局资源还要"是你的"（房间局则是"同房间的人"）。**

---

## 2. 鉴权三层

```
第一层 · 身份      JwtAuthFilter（Scope=DEBATE / DEBATE_WRITE）
                   └→ 无令牌 / 令牌失效 = 401 UNAUTHORIZED
第二层 · 身份来源   Controller 一律 UserContext.requireId()（JWT 的 sub）
                   └→ 请求里的 userId / userName **一律忽略**（不是报错，是忽略）
第三层 · 归属      MatchAccess.requireAccess(matchId, userId)
                   └→ 不是这场的人 = 403 FORBIDDEN
```

**全项目只走这两个入口**，任何 Controller 不许自己拼 SQL 判断身份或归属：

```java
String userId = UserContext.requireId();          // 取身份
matchAccess.requireAccess(matchId, userId);       // 校验归属
```

## 4. 归属规则：为什么不能只看 `sy_match.user_id`

房间局**只有一条 match**，而且是"谁点开局就记在谁名下"
（`RoomService.start()` → `matches.create(房主, ...)`，再用 `sy_room.match_id` 存住关系）。
所以两条判据任一成立即放行：

```sql
-- ① 单人局：我是这条 match 的 owner
select count(*) from sy_match where id = ? and user_id = ?

-- ② 房间局：这条 match 属于某个房间，且我在那个房间的席位上
select count(*) from sy_room r join sy_seat s on s.room_code = r.code
 where r.match_id = ? and s.user_id = ?
```

实现：`com.siyige.auth.MatchAccess#canAccess`；不通过时 `requireAccess` 抛
`403 FORBIDDEN`（错误码 `FORBIDDEN`）。

**401 与 403 严格分工**：401 = 你没登录（过滤器）；403 = 你登录了但这场不是你的（`MatchAccess`）。

## 5. SSE 的令牌传递

浏览器 `EventSource` **不支持自定义请求头**，所以 `/events` 额外接受查询参数：

```
GET /api/matches/{id}/events?token=<jwt>
```

- **只对路径以 `/events` 结尾的请求生效**。同一个令牌放到别的接口上（如
  `GET /api/matches/{id}?token=...`）**不被承认** → 401。
- 有 `Authorization` 请求头时**优先用请求头**，不会去看查询参数。
- 风险（已接受）：令牌会进访问日志与浏览器历史。缓解手段：令牌 2 小时有效、只在 SSE 端点开口子。
  要更严就得改成 fetch 读流手写 SSE 解析（丢自动重连），本期不做。
- 前端在未登录时不建立 EventSource，`onerror` 时若未登录会主动 `close()`，避免无限重连刷 401/403。

## 6. 昵称与房主判断

| 项 | 规则 |
|---|---|
| 昵称来源 | 一律查 `sy_user.name`（`UserNames#name`）。**不再使用**「房主」「玩家」这类字面量名字 |
| 席位显示 | `left join sy_user u on u.id = s.user_id` + `coalesce(u.name, s.user_name)`：真人取当前昵称（改名即时生效），AI 席位与已删账号走 `user_name` 快照兜底 |
| 角色标签 | 「房主 / 玩家」改成昵称旁边的**小标签**（`.tag`），不是名字 |
| 房主免准备 | 按**座位 A1** 判断（`RoomService.HOST_SEAT`）。**禁止**再写 `name.equals("房主")` 这类比较 |

> 为什么强调：昵称换成真账号昵称后，`removeIf(n -> n.equals("房主"))` 永远不成立，
> 房主会把自己算成"未准备"，**房间永远开不了局**。这是 D3 修复的核心 bug，有单测钉住
> （`RoomNicknameTest.房主未准备也能开局_因为免准备按座位A1判断`）。

## 7. 数据与老数据

- **表结构零改动**：`sy_user.id` 与 `sy_match.user_id` / `sy_record.user_id` / `sy_diag.user_id` /
  `sy_seat.user_id` 全是 `varchar(32)`，同型。
- **不认领老数据**：`u1`、`gXXXXXX` 这类历史对局/记录**不迁移、不删除、不合并**，
  它们不属于任何登录账号，所以现在**谁都进不去**（访问返回 403）。需要清理时另写 SQL。

## 8. 错误码

| code | HTTP | 场景 |
|---|---|---|
| `UNAUTHORIZED` | 401 | 未登录 / 令牌无效 / 已登出 |
| `TOKEN_STALE` | 401 | 令牌签发于改密之前（见认证契约 §2.1） |
| `ACCOUNT_DISABLED` | 401 | 账号被全站封禁 |
| `NOT_ADMIN` | 401 | 拿管理员令牌访问对局接口（不能当匿名放行） |
| `FORBIDDEN` | 403 | 登录了，但这局不是你的（既不是 owner，也不在该房间席位上） |
| `NOT_HOST` | 409 | 非房主点「开始辩论」 |
| `NOT_READY:<names>` | 409 | 还有真人没准备（`names` 是**昵称**列表，房主不在其中） |
| `ROOM_FULL` / `ROOM_STARTED` / `ROOM_NOT_FOUND` / `NOT_IN_ROOM` | 409/404 | 房间状态类错误（原有语义未变） |

## 9. 前端约定

| 场景 | 行为 |
|---|---|
| 未登录进 单人 / 房间 / 对局 / 复盘 / 诊断 / 记录 页 | 整页显示「登录后可见」+ 去登录按钮，不渲染操作面板 |
| 未登录点「开始辩论 / 建房 / 加入房间 / 自定义辩题送审」 | `needLogin()` → toast 引导文案 + 跳登录页 |
| 身份 | 一律 `S.user.id`；**不存在** `S.userId`，也不再读写 `localStorage['sy_uid']` |
| 请求体 | 不再携带 `userId` / `userName`（后端也会忽略） |
