## 1. 为什么必须动辩论侧

需求是「未登录不能玩 + 只有本人（或同房间的人）能看能操作对局」。这两条都落在辩论侧的代码里：

| 需求 | 必须改的地方 |
|---|---|
| 未登录不能玩 | `/api/matches`、`/api/records`、`/api/diag`、`/api/rooms` 要挂鉴权 |
| 身份唯一来源 | 这几个 Controller 现在从 `body/query` 读 `userId`，要改成从令牌取 |
| 对局归属 | 每个 `/api/matches/{id}/**` 都要判断「你是不是这场的」 |
| 房间昵称 | 前端传的 `userName:'房主'` 要换成账号昵称，房主判断不能再靠名字 |

所以改动是**跨线协作**，不是社区线顺手加个功能。

## 3. 对辩论方的三条约定（以后新增代码请照这个来）

### ① 新增 `/api/matches/{id}/**` 接口，入口必须加归属校验

```java
String userId = UserContext.requireId();          // 401 由过滤器负责
matchAccess.requireAccess(matchId, userId);       // 403 由这里负责
```

漏了这一步 = 任何人都能操作别人的对局。

### ② 新增接口不要再读 `userId` / `userName`

```java
// ❌ 旧写法
String userId = String.valueOf(body.getOrDefault("userId", "u1"));
// ✅ 新写法
String userId = UserContext.requireId();
```

### ③ 新增「匿名可访问」的接口时，**不要**给它注册过滤器

鉴权靠「不注册」实现（见 `AuthFilterConfig` 的注释）。如果改成 `/*` 再逐个放行，漏一个就是漏洞。

## 4. 回滚方式

这一轮是**一个 commit**（`993f665`），回滚只需：

```bash
git revert 993f665     # 注意：会连带回滚 Redis 密码配置，需手工保留那 3 行
```

前端身份相关（`S.userId` 删除）与后端鉴权是**成对**的：只回滚一半会出现「前端没身份 / 后端要身份」的错配。
