# 前端体验改动清单（2026-11-14）

来源：把另一款 App 的 8 条 UX 优化经验，**只提取思弈阁用得上的部分**，不加新功能。

每条都写清楚：原问题 → 改法 → 落到哪个文件 → 怎么验证。

---

## 已采纳（5 条）

### 1. 搜索框从"常驻一行"改成"右上角按钮"

**原问题**：视频页顶部常驻一条搜索框，占掉一整行高度，也是误触源；用户实际很少一进来就搜。

**改法**：默认收起，右上角一个「🔍 搜索」按钮；点开才出现输入框并自动聚焦，点「收起」回到信息流。

**文件**：`web/src/views/VideoView.vue`（模板 `vtop` / `searchOpen` / `toggleSearch`）

**验证**：
```
默认有输入框: false        ← 收起
右上角有搜索按钮: true
点开后出现输入框: true
输入框自动聚焦: true
收起后输入框消失: true
```

---

### 2. 危险动作加二次确认

**原问题**：「放弃这一场」和「退出登录」都是**一点就执行**的破坏性动作，没有回退。

**改法**：调起系统确认框，文案写明后果。

```
放弃对局：这一场的进度会丢失，已扣的费用按已用量结算，不可恢复。
退出登录：退出后需要重新登录才能继续训练，本地不会丢数据。
```

**文件**：`web/src/views/SoloView.vue`、`web/src/views/MeView.vue`

**验证**：
```
退出登录弹确认: true   「退出登录？…不会丢数据。」
```
（放弃对局同款写法，未单独弹窗验证，因为要先有一场进行中的对局）

---

### 3. 失败原因就地显示，不只靠 toast

**原问题**：登录失败只有右上角 toast，2 秒就消失；用户填完表单往下看，会觉得"点了没反应"。

**改法**：错误原因同时显示在提交按钮正下方（红底浅框），toast 保留。

**文件**：`web/src/views/LoginView.vue`（`authError` / `.auth-err`）、`web/src/style.css`

**验证**：
```
页面内错误提示: 账号或密码不对
```

---

### 4. 分数用主色，不用错误红

**原问题**：分数块没设颜色就跟着全局走，低分看起来像"报错"。

**改法**：总分统一主色 `#2f5bea`；分数缺失时显示「待出分」而不是空白。

**文件**：`web/src/views/ReviewView.vue`（`.score-color`）、`web/src/style.css`

**验证**：
```
有 .score-color 元素: true
颜色: rgb(47, 91, 234)
```

---

### 5. 正式版隐藏测试期入口

**做法**：视频「审核台」按钮由后端 `consoleEnabled` 控制（默认 `false` 就不渲染），不在前端写死。

**文件**：`web/src/views/VideoView.vue`（`v-if="consoleEnabled"`）、后端 `siyige.video.audit.console-enabled`

**未改**：其余"测试期入口"（如接口探测）思弈阁本来就没有，不存在需要隐藏的东西。

## 未采纳（3 条，附原因）

### 6. 「整块可点 → 固定按钮」

**思弈阁现状**：辩题卡片确实整块可点（点任意位置都开局），语义上属于同类问题。

**为什么不改**：卡片上已经有明确的「开练 →」文字，且**整块点击是列表页的通用交互**（比"只能点小的"更好按）。真正的问题是"点错题就开局"，但那由**开局后的退出机制**兜底（对局页有「退出」，现在也加了确认）。如果改成只能点小按钮，手机上反而更难按。

**留作后续**：如果真出现"误触开局"，再改成「点卡片选中、点开练开局」两段式。

### 7. 「一个页面两个同类按钮，删掉一个」

**思弈阁现状**：没有真正的重复入口。可能的候选：

- 单人页有「用这个题开练」（自填题）和题库卡片的「开练」——**用途不同**（一个是自定义题，一个是选题库）
- 复盘页底部有「再来一场 / 看能力画像 / 辩论记录」，和侧栏重复——**这是导航冗余，不是状态冲突**，移动端尤其需要（侧栏在手机上收起了）

**结论**：不删。

### 8. 「顶部只留一个输入框（去掉标题/说明/列表）」

**那条经验来自"填 id 读取"的内部工具页**。思弈阁的页面是给辩手用的产品页，标题和说明是必要信息（尤其新用户不知道"辩题"怎么选）。

**结论**：不适用。

## 一句话总结

采纳的 5 条都在**"减少误触 + 让反馈就地可见"**：搜索收起、危险动作确认、错误提示贴按钮、分数用主色、测试入口按开关隐藏。

没采纳的 3 条是因为**思弈阁的场景不同**（列表页整块点击是优点、没有真正的重复入口、产品页需要标题说明），不是"没做"。
