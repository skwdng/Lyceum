## 0. 一句话结论

**赛制顺序本身是对的，坏的是「每一步只能发生一次」这条不变量——它在写库层、状态机层、前端展示层三处都没有被保证。**

- 后端：同一 step 可写两条发言；抢拍可以把发言权塞给集合里的第一个席位（不是抢的人）；全真人一侧的自由辩窗口过期后会永久卡住。
- AI：「说到一半断掉」不是网络问题，是 prompt 让模型写 320 字、护栏按 260 字硬切，切点还不落在句读上。
- 前端：打字机一条约 6.5–9.7 秒，AI 接话间隔 3.0–7.5 秒 → 每一句都早于上一句打完到达，串行播放导致稳定积压（17 个 AI 轮累计约 60 秒）；未轮到打字的发言在列表里被整段隐藏，观感就是「上一句消失 / 顺序乱了」。

## 2. 用户点名的四类症状 → 根因

| 症状 | 直接原因 | 根因 | 证据 |
|---|---|---|---|
| **发言中「说到一半断了」** | prompt 写「输出 220–320 字」，护栏按 `min(Persona.maxChars, segCharCap)=260` 硬切；无句读长句走 `substring(0,260)+'。'` | R-AI-1 字数三处来源（`segChars` / `segCharCap` / `Personas.maxChars`）互不对账 | 02 §1①，`AuditAiSpeechTest.无句号时截断切在词中间` |
| **发言「上一句凭空消失」** | `turnsView` 只渲染到「第一条还没打完的发言」为止（`debate.js:212-236`），后面的发言整段隐藏 | R-FE-1 用「隐藏」代替「排队」，隐藏范围过大 | `debate.js:233-236`；03（见文末） |
| **顺序乱 / 同一句叠两遍** | 同一 step 可写两条；前端只按 (step,seat) 去重 | R-BE-1 步骤唯一性缺失（`submit` 无 `hasTurn`、`updateStep` 无 CAS、超时分支无 `hasTurn`） | 01 §2 #1/#2；`AuditConcurrencyTest.同一步双发会写出两条发言` |
| **房间自由辩「我说不了话 / 席位不对」** | `buzz()` 取 `my_seats.iterator().next()`，不是抢拍者 | R-BE-2 席位归属只有「我坐哪儿」，没有「谁在抢」 | 01 §2 #4；04 F2（turn13 `A1≠A2` 实测） |
| **自由辩卡住不动** | 窗口过期且该席位是玩家、同侧无 AI → `aiSeat==null` 直接 return | R-BE-3 抢拍阶段没有超时兜底 | `MatchService.java:326`；`AuditConcurrencyTest.自由辩全真人时超时卡死` |
| **催一下「点了没反应」** | AI 正在生成时 skip 仍返回 `ok:true`，但 tick 被 `generating` 挡掉；`skipped_step` 已记账 → 不会再触发 | R-BE-4 催一下与生成线程零交互 + 假成功 | `MatchService.java:353,600-603`；01 §4 #20 |
| **催一下「连点很多次都生效」** | `last_skip_at` 是 bigint，`num()` 走 `intValue()` 截断 → 冷却判据失真 | R-BE-5 bigint 被 int 截断 | 01 §3 #15；04 F1（并发 5 次全 `ok:true`） |
| **刷新后整场重新打字** | `typed`/`shown` 在 store 里，刷新即重置 | R-FE-2 播放进度没有持久化（只持久化 matchId/草稿） | `debate.js:126-127,619-647` |

## 4. P1（同批修，或紧接着）

**后端 / 状态机**
1. `skip` 冷却被 `num()` 截断 → 用 `numLong()`（`MatchService.java:592`，`bill_tokens`/`token_base` 同病）。
2. `skip` 读-改-写无 CAS → 并发 5 次全 `ok:true`（04 F1）；用 `update ... where skipped_step != step` 当闸门。
3. `finish` 无幂等闸门（双路径并发 → 双结算 + 画像 streak+2）。
4. `ABANDONED/FINISHED` 仍可 `submit`（`submit` 只判 `cur==null`）。
5. 开局 `turnSeconds` 只在第 1 步生效（`advance` 恒传 0）。
6. 时间口径三套：`Format.Step.sec`(180) / `Pace`(300) / AI 回合硬编码 2 秒。
7. 生成失败 3 次直接判 `ABANDONED` 且不发 `match.end` → 用户看到「对局突然没了」。
8. `String.valueOf(getOrDefault(...))` 把 JSON `null` 变成 `"null"` → `kind="null"`，单人局失去不限时/催一下。

**AI**
9. `cutRepeats` 误杀结辩收束句与质询重复追问（判据「同句第二次出现即断」，连后面全砍）。
10. `QuoteGuard` 缺「否定词/数字指纹」：插「没有」仍 0.90 判命中；出处豁免（书名号/「据」）对整条引文免检。
11. 兜底模板只看 `side+seg`，不看 duty → 质询「答」抽出提问句；无 key 时 8 席只剩 10 个池。
12. 打字机 8.2–9.7s vs 接话 3.0–7.5s → 稳定积压（17 轮 ≈60s），「下句压上句」。

**前端**
13. `turnsView` 用 `firstUntyped` 截断列表 → 未轮到打字的发言整段不渲染（「凭空消失」）。
14. 刷新后 `typed/shown` 重置 → 整场从头再打一遍。
15. `forceFull` 把「我发言之前的所有 AI 气泡」一次性补全 → 观感上「唰一下全出来」。

## 5. P2 / 待观察

- `seq` 用 `max+1` 非原子（SSE 补发可能重号/丢事件）。
- `attempts` Map 永不清理（长跑泄漏）。
- `point` 未校验 step 落在 `1..当前`。
- 房间两端 `waitingForMe` 同时为 true（04 观察项）。
- 替对方提交返回 409 而非 403/400（契约不一致，前端只认 409 也可，但要写进契约）。
- `judges` token 恒 0、`join()` 无总超时（最坏 60 秒）。
- `ai-think-ms: 700` 是死配置（`thinkMs()` 零调用）。
- 老库 `query_rounds=4` 被夹到 2 → 老对局步数从 26 变 18，直接 finish。
