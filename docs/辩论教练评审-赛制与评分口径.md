## 0. 三条结论（先看这个）

**① 赛制骨架是比赛，时间与字数刻度是练习。**
18 步的**顺序**（立论 → 驳立论 → 质询 → 自由辩 → 反方先结辩）与大陆主流 4v4 赛制高度一致，这是"像比赛"的部分。但**字数上限**是按"打字产能"定的：立论 260 字 ≈ 62 秒口语，而真实立论是 3 分钟、约 700–900 字（`Format.java:53` 对 `Pace.java` 的 40 字/分钟口径）。也就是说，现在训练的是"在 3 分钟的位置上写 1 分钟的稿"，练的是结构，不是密度。**不改代码可做**：给每个环节加"第二把尺"文案（目标字数 ≈ 口语时长），见 §1.4-②、§1.5。

**② 「表达」15 分是虚维，且从未被评测验证过。**
现状 `manner`（表达维）只算句长与口癖（`ScoreService.java:239-255`），文本媒介下这是对"听感"的冒名；而**唯一的外部校准**（`docs/评分有效性评测报告.md:31` 的四档标注口径）只标注判准/证据/回应/追问四项，**完全不标"表达"**。所以这 15 分既无证据来源、也无有效性证据。建议更名「语言」并降到 10 分，把 5 分给「应变」（20→25）；"仪态"在无视频证据的前提下**明确不进总分**。见 §2.4。

**③ 抓漏现在是"校对"，不是"听漏"。**
5 类漏洞对应 5 句固定埋雷句（`FlawService.java:24-30`），**永远追加在 AI 发言末尾**（`FlawService.java:46`），类型按字符串精确匹配（`FlawService.java:50`）；`point()` 没有次数限制，且响应里回传了正确答案 `correct`（`MatchService.java:411-418`）。结果是：任何客户端 2 次调用即可 100% 命中，人类玩家 2–3 场就能背下 5 句。训练价值在第 3 场归零。补 2 类 + 首答口径见 §3。

### 1.2 三种真实赛制骨架对照

| 元素 | **新国辩**（新加坡国际华语辩论赛，4v4） | **大陆世界杯系 4v4**（含驳立论的一族） | **奥瑞冈**（Oregon，3 人制） | **思弈阁现行 18 步** |
|---|---|---|---|---|
| 环节序列 | 正一立论 → 反一立论 → **正二质询反方** → **反二质询正方** → 自由辩论 → **反三小结 → 正三小结** → 反四结辩 → 正四结辩 | 立论 ×2 → **驳立论 ×2** → 质询/盘问 ×2 → 自由辩论 → 结辩 ×2 | 申论 ×3（每人一段）→ 每段后**一对一交叉质询** → 结辩 ×2 | 立论 ×2 → 驳立论 ×2 → 质询 ×8 步 → 自由辩 ×4 步 → 总结 ×2 |
| 质询归属 | **二辩**质询 | 二辩或三辩（各赛略异） | 每位申论者都被对方一对一质询 | **三辩**（二辩不参与质询） |
| 质询后小结 | **有**（三辩，2 分钟，反方先） | 多数有（盘问小结） | 无独立小结，融入结辩 | **无** |
| 结辩顺序 | 反方先、正方后 | 反方先、正方后 | 反后、正后（负方先） | **反方先（B4）→ 正方（A4）** ✅ |
| 时间骨架 | 3-3-3-3-4-2-2-4-4（分钟） | 3-3-2-2-1.5~3-4-4（各赛微调） | 申论 5-6、质询 3、结辩 4（各赛微调） | 字数上限 260/200/100-120/140/280；房间计时见 §1.1 |
| 评分维度 | 立论完整 / 攻防效率 / 战场掌控 / 回应完整 / 结辩说服力 | 内容 · 交锋 · 表达（各赛权重不同） | **内容 : 语言 : 台风 ≈ 4 : 3 : 3** | 立论 25 / 论证 30 / 表达 15 / 应变 20 / 论据 10 |
| 政策辩支持 | 部分 | 部分 | **核心**（需/根/解/损四步） | **无对应判据** |

> 新国辩骨架依据：[Ch 1 — 新國辯是什麼](https://github.com/yPin9/Learning-with-Claude/blob/main/debate/chinese_debate/01-what-is-xinguobian.md)（各届细节略有出入）。华辩世界杯/奥瑞冈的分钟数以当届规程为准，本表只比**结构**，不比秒数。

**一句话定位**：现行 18 步属于**"大陆世界杯系"**（有独立驳立论环节），而不是新加坡新国辩（没有驳立论，但有三辩小结）。所以对照时最容易被打的两处是：**漏了"质询小结"**、**质询给了三辩而二辩闲置**。

### 1.3 「像比赛」的 6 处（有据可查）

1. **反方后立论**：A1 → B1，反方获得"先听再立"的后手权（`Format.java:26-31`）。
2. **驳立论紧跟立论、先破后立**：第 3、4 步，顺序与主流赛制一致（同上）。
3. **质询在驳立论之后、自由辩之前，且问/答双向轮转**：`QUERY_PAIRS` 是 `{A3→B3}`、`{B3→A3}`（`Format.java:37-40`），双方都既问也答，不是单向盘问。
4. **反方四辩先结辩、正方后结**：`Format.java:94-95` 顺序为 B4 → A4，与真实赛制一致（后手方收尾）。
5. **超时不判负、只落 `TIMEOUT` 占位**（`MatchService.java:335`），且打字可续命但有上限（`Pace.MAX_EXTEND = 3`，每次 +30s）——这正好模拟了"时间压力真实存在，但赛场允许你补救"。
6. **房间自由辩有抢拍**：8 秒窗口，AI 要等窗口剩 35% 才开始抢（`MatchService.java:317-328`、`473-476`）——真实自由辩就是抢话，这个机制是对的。

### 1.4 「像练习」的 9 处 + 对应改法

每条都给：**现象 → 为什么像练习 → 文案级改法（不动代码）→ 效果**。

**① 两套时间刻度并存**
现象：`Format.sec` 求和 24.7 分钟，`Pace` 求和 51 分钟，房间实际走后者；单人走 0（不限时）。
为什么像练习：用户看到"24 分钟一场比赛"，实际打了 51 分钟，或者根本没计时。**同一个产品对外说三种时长**。
改法：`docs/SPEC.md` §3.1 表格下加一行说明——"`步时长` 是赛制骨架（用于展示），`实际计时` 按打字产能换算（40 字/分钟）；房间约 50 分钟，单人演练不限时"；README「18 步赛制」改成「18 步 + 房间约 50 分钟 / 单人自定节奏」。
效果：用户不会再拿"24 分钟"去规划一场训练。

**② 字数上限是打字口径，不是口语口径**
现象：立论 260 字（`Format.java:53`）。按 250 字/分钟的口语语速，260 字只够说 **62 秒**；真实立论 3 分钟 ≈ 700–900 字。全场上限合计 2920 字，真实 4v4 一场约 6000–9000 字——**只有 40%**。
为什么像练习：练的是"提纲"，不是"说满三分钟不重复"。
改法：输入框下方加第二把尺（纯文案）：「目标 550–750 字 ≈ 3 分钟口语；当前 260 字上限是**演练档**」；同时给 AI prompt 加同等一句，让 AI 示范的密度对得上。**不要改 `segCharCap`**（那会动引擎）。
效果：用户在"演练档"之外知道"比赛档"长什么样，这才是训练迁移。

**③ 单人主路径没有倒计时**
现象：`stepSeconds` 对 `kind=solo` 直接返回 0（`MatchService.java:854`）。而 SOLO 是 SPEC 明写的主路径（`SPEC.md:234`）。
为什么像练习：产品宣称的核心价值是"赛制演练"，但主路径没有任何时间压力，只有篇幅约束。
改法：SOLO 开局面板加一行字：「演练模式：不限时，可反复改；想要时间压力请开计时（房间/计时开关）」——**承认这是取舍，别假装是比赛**。
效果：避免"在无压环境练出来的稿，上场写不出来/说不出来"的迁移落差被用户自己发现。

**④ 质询没有追问，是两个独立提交步**
现象：质询 = "问"一步 + "答"一步，各自独立提交、独立评分（`Format.java:81-86`）。100 字问、120 字答。
为什么像练习：真实的质询是**连续封闭提问 + 对方回避时立刻追问**，训练价值 80% 在追问。现在是"你问一段、他答一段"，等于两次小申论。
改法（文案）：质询 prompt 与 UI 提示卡改成——「连发 3–5 个封闭问题（只能用"是/否"回答），每问 ≤25 字；发现对方答非所问，第一句就是追问：「您没有回答，我问的是……」」。
效果：不改引擎也能把行为引导到"逼问"上；追问能力的真实现要靠 §5.2 的 P2-1（追问轮）。

**⑤ 质询归属错位 + 缺"质询小结"**
现象：质询全部由三辩执行（`Format.java:37-40`），二辩整场只有 2 步；且质询之后直接进自由辩，没有任何环节要求"结算质询战果"。
为什么像练习：新国辩是**二辩质询 + 三辩小结**。少了小结，质询里逼出来的"对方承认"从不被登记成战果，裁判（AI/规则）也就无从计分。
改法（文案）：
- 席位说明里写清"本产品由三辩承接质询（对应新国辩的二辩质询 + 三辩小结合并）"；
- 总结环节 prompt 与 UI 卡强制开头 30 字交代战场：「质询中对方承认了 ___，未回答 ___；自由辩我方守住 ___」。等于把"小结"压进结辩。
效果：质询的战果第一次进入评分视野（应变维的"点名+引述"判据会随之变准）。

**⑥ 自由辩 = 4 个独立短步，不接上一句**
现象：`FREE_SEATS` 四席轮转，每步 25 秒/140 字（`Format.java:33-34`、`90-92`）；140 字在 25 秒内说不完（约 34 秒口语）。
为什么像练习：真实自由辩是"接话—反打—换战场"，一句不接就断链。
改法（文案）：自由辩 prompt 强制「第一个 15 字必须引对方上一句原话（可用简称）」；字数提示改「≤90 字（25 秒真说得完）」。
效果：把 140 字压到 90 字，才符合它自己的 25 秒。

**⑦ 没有"修论 / 中场调整"的强制动作**
现象：驳立论只要求"打掉对方最强点"，没有要求"说明我方论点改没改"。
为什么像练习：真实赛场驳立论阶段，强队一定会做**修论**（承认被打掉的、换掉守不住的）。这是新手与熟练者最明显的分界。
改法（文案）：驳立论 prompt 加一句「必须明确：我方删掉/修改/保留哪一条论点，为什么」。
效果：一次发言同时训练"攻"和"自守"。

**⑧ 跨阵营自辩不判胜负，但 UI 仍在暗示比分**
现象：`R-SOLO-06` 明写不判胜负（`SPEC.md:241`），但结算页仍以总分为主视觉。
为什么像练习：自己打自己还比输赢，会让用户把注意力放到"刷分"而不是"补弱"。
改法（文案）：8 席/跨阵营时，结算页标题改「自辩演练 · 不计胜负」，总分旁加"（仅评个人完成度）"。
效果：与 §6.4「只和自己比」的原则一致。

**⑨ 政策辩没有判据**
现象：评分五维里没有"需/根/解/损"（政策四问）的落点；`SLOGAN` 词表里却能命中"内卷""电子毒品"这类**辩题核心词**（`ScoreService.java:54`）。
为什么像练习：遇到政策题，用户只能靠"价值升华"得分，训练方向被带偏。
改法（文案）：论据卡/作战卡加一栏「政策四问：需求是否存在 / 根因是否被抓准 / 方案是否可行 / 损害是否可接受」，并在辩题卡上标"政策题 / 价值题"。
效果：政策题有了可观察的答题骨架。

## 2. 评分口径

### 2.1 先看数学事实（这些决定了"权重"有没有意义）

从 `ScoreService.java:117-157` 可完全复现：

```
total = round(matter×0.25 + method×0.30 + manner×0.15 + adapt×0.20 + evidence×0.10)
        + collab(0..3) + flawBonus(0..9)
每维 clamp 到 [30, 95]；total 上限 100；okTurns==0 → total = 0
```

由此得到五个**必须写进口径文档**的推论：

1. **满分靠奖励，不靠维度**：五维全 95 → 95 分；要摸到 100 必须靠协同 +3 与抓漏 +9。也就是说"完美发言"在纯维度上封顶 95。
2. **地板是 30，不是 0**：一次有效发言（哪怕 1 个字）起步就是 30 分。只有"整场零有效内容"才归 0（`okTurns==0`，`ScoreService.java:157`）。
3. **抓漏的 9 分 ≈ 表达维度的整段跨度**：表达权重 15 × (95−30) = 9.75 分。抓漏三连对 = +9 分 = 把"表达"从地板抬到优秀的全部收益。**一个 5 选 1 的识别题，与一个维度的全幅等值**——这是权重设计的失衡点，不是抓漏太重要，是表达太轻。
4. **实测分布比标称刻度低一档**：`docs/评分有效性评测报告.md:54` 实测 **优秀 59–70 / 中等 42–49 / 较差 38–43 / 敷衍 0**。即规则引擎的"优秀"只有 ~65 分。若 rubric 把"优秀"写成 ≥85，则**永远打不到**——不可达的判据等于没有判据。所以 `rubric-v3` 的语义档边界写 75/50，同时用 `calibration.observed_anchor`（59–70 / 45–58 / ≤44）作为重标前的临时锚点，两者不混用。
5. **档位区间自相重叠**：报告里"中等 42–49"与"较差 38–43"在 42–43 重叠（同报告 §四-① 只修了敷衍档）。三档必须互斥，否则同一条发言可以被判两档。

### 2.2 五维权重 25 / 30 / 15 / 20 / 10 逐维判定

| 维度 | 现状 | 真实赛制对照 | 判定 | 理由 |
|---|---|---|---|---|
| 立论 matter | 25 | 新国辩"立论完整性"、奥瑞冈"内容" | **合理** | 内容系主项，25 与"内容 40%"的一半相当；且判据（判断句 + 判准）可规则化 |
| 论证 method | 30 | 同上（攻防效率的底子） | **合理，且应保持最大项** | 训练产品最该抓的是"因果链"，30 让"会推"压过"会说" |
| 表达 manner | 15 | 奥瑞冈"语言 30%"、世界杯系"表达" | **偏高且不可判** | 文本媒介只测得到句长/口癖；评测基准不标此项（`评分有效性评测报告.md:31`）。**建议 → 10（更名"语言"）** |
| 应变 adapt | 20 | 新国辩"攻防效率/战场掌控"、世界杯系"交锋" | **偏低** | 产品自己说"抓漏是核心训练动作"（`FlawService.java:9-13`），交锋却只有 20；新手最大缺口也在这里。**建议 → 25** |
| 论据 evidence | 10 | 奥瑞冈"内容"里的证据项 | **低但可接受** | 受 48 张卡片库限制，权重高会变成"背卡比赛"；但**编数字的惩罚不该放在这 10 分里**（见 §2.5-①） |

**结论**：25/30/15/20/10 的**排序**是对的（论证 > 立论 > 应变 > 表达 > 论据），**问题在两处错配**——表达虚高（给了一个不可稳定判定的量 15 分）、论据虚低（却承担了"编数字倒扣"的全部宣示）。建议 **25 / 30 / 25 / 10 / 10**（立论/论证/应变/语言/论据）。

### 2.3 每维三档的可观察判据（要能被规则或人工稳定判定）

标注：**R** = 现有规则可判（有对应正则/计数）；**R\*** = 规则可判但需补条件；**H** = 只能人工判；**R+H** = 规则给候选、人工定档。
档位锚点采用**双刻度**：`语义档`（判据本身）+ `现行实测分`（`评分有效性评测报告.md:54` 的分布，避免写出不可达的阈值）。

#### 立论 matter（建议 25）

| 实测锚点（v3 重标前） | 优秀 59–70 / 合格 45–58 / 待改 ≤44 | — |

#### 论证 method（建议 30）

### 2.4 「表达」该不该并入语言 / 仪态？—— 三个方案 + 推荐

先把事实摆清：

- 现行"表达"测的是**句长 + 口癖**（`ScoreService.java:239-255`），这是"语言"，不是"表达"的更宽含义。
- **仪态在文本产品里没有证据源**：本产品没有视频采集，`R-VOICE` 只到转写文本（`SPEC.md:204-213`）。所以奥瑞冈式"台风 30%"在这里**不可观测**，任何给它打分的做法都是编分。
- 唯一的外部校准（80 条人工四档）**不含表达项**（`评分有效性评测报告.md:31`）。换句话说，表达这 15 分的**有效性从未被验证**，也没有"变好/变坏"的判据。

| 方案 | 做法 | 优点 | 致命问题 |
|---|---|---|---|
| A 并入论证 | 表达降为论证的**系数**（句式差 → 论证分 ×0.9） | 总分更干净 | 会把"说得好"和"想得清"混成一个数，复盘无法归因，违反 `R-SCORE-03` |
| **B 更名 + 降权（推荐）** | 更名「语言」10 分；仪态**明确不进总分**；5 分给应变 | 名字与判据对齐；分数可归因；与"抓漏是核心"的产品主张对齐 | 需重标定档位锚点（v2↔v3 不可直接比） |
| C 只在语音回合计分 | 打字回合语言分 = 诊断标签（不进总分），语音回合才计入 | 最严谨：有音频证据才判听感 | 依赖语音普及率；现在会让大量用户该维度空缺 |

**推荐 B 作为 v3 口径，C 作为 v3.1 路线**（等语音回合占比上来再切）。理由：B 是唯一既保留"可归因"又不编分的方案；C 在语音覆盖率不足时会制造"维度缺失"，反而破坏五维雷达的可比性。

**迁移口径（必须写进版本说明）**：v3 生效后，五维分**不可与 v2 历史直接比较**——权重变了、档位锚点重标了。`能力分析` 的"与上一场对比"应在 v3 上线后 30 天内标注"口径已更新"，或干脆只比较 v3 之后的场次（对应 `R-MOT-01` 的"只和自己比"，不能自己和自己用两把尺）。

### 2.5 五处口径冲突（不统一，rubric 就没有约束力）

**① 编数字的惩罚是双轨的**
- AI「论据裁判」：出现无法核查的具体数字 → **直接扣到 50 分以下**（`JudgePersonas.java:63`）。
- 规则引擎：`evidence = max(20, clamp(40 + cited×10) − 8×fabricated)`（`ScoreService.java:134-136`），即编 1 个数字扣 8 维度分 = **总分 −0.8**。
- 用户会看到"论据裁判说 42 分、规则给 84 分"。
- **统一建议**：编数字改为**总分层 guard 扣分**：`−3/条，上限 −9`（与抓漏 +9 对称），并在复盘点名原串。这样"最严重扣分项"才真的是最严重。

**② 抓漏词表与自动检出词表分裂**

| 埋雷判定（`FlawService.TYPES:18-19`） | 自动检出（`ScoreService.detectFlaws:286-299`） | 问题 |
|---|---|---|
| 未证前提 | 未证明前提 | **同一类两个字符串** → 错题本会分裂成两项（`R-MOT-03` 统计失真） |
| 以偏概全 | 以偏概全 | 一致 |
| 诉诸权威 | 诉诸权威 | 一致 |
| 偷换概念 | — | 只在埋雷侧 |
| 循环论证 | 同义反复 | **不同概念**：循环论证是逻辑病（前提含结论），同义反复是修辞病（重复自己）；现状实现用 4-gram 重合 >0.6 判"同义反复"（`ScoreService.java:294-297`），与埋雷句"这个方案是合理的，因为它确实很合理"也不严格同类 |
| — | 未回应对方 | 只在检出侧 |

**统一建议**：以 `FlawService.TYPES` 为唯一词表（用户看到的是这 5 类），`detectFlaws` 只作为"自动提示"映射到同一 key；"同义反复"作为 `循环论证` 的子判据（`sub_type`），不另立类目。

**③ 维度口径有三套**
`SPEC.md` §6.2 说五维；README:59 说**六维雷达（含协同）**；`JudgePersonas` 是**四视角**。四视角与五维的真实映射是：

| AI 裁判 | 覆盖的维度 | 缺口 |
|---|---|---|
| 结构裁判 structure | 立论 + 论证 | 两维合一，**没有独立的"论证"视角** |
| 交锋裁判 clash | 应变 | 覆盖 |
| 表达裁判 delivery | 表达（语言） | 覆盖 |
| 论据裁判 evidence | 论据 | 覆盖 |
| — | **无** | 立论与论证无法分别校验 |

**建议**：rubric-v3 明确"**五维是唯一计分口径**"；协同（0–3）与抓漏（0–9）是**训练加分**，单列不进权重；AI 四裁判只产出"评语 + 分歧度"，**不产出与规则并列的总分**。

**④ 两套总分并存且锚点不同**
规则引擎"优秀 ≈ 59–70"（`评分有效性评测报告.md:54`），AI 四裁判等权平均后典型 65–80（`AiJudgeService.java:83-89`，且四家人设的锚点是 80+/60-79/40-）——同屏会出现"五维总分 63 / 评审团 78"两个数，用户无法解释差在哪（违反 `R-SCORE-03`）。
**建议（文案）**：结算页主分数只出规则分；评审团区标题改「评委评语（4 视角，仅供参考）」，并显示"分歧度 22 分 → 本场有争议点"这类**分歧**而不是第二个总分。

**⑤ 关键词误伤：辩题核心词被当口号**
`SLOGAN` 词表含 `内卷 / 电子毒品 / 落后`（`ScoreService.java:54`）。而评测集里的"优秀档"样本恰恰以「先界定：内卷指『投入持续增加而总收益不变』」开头（`score-dataset.json:379`）——它命中 `SLOGAN`，被 `matter` 扣 20 分（`ScoreService.java:221`，因为 `EXAMPLE` 与"据"都没出现，而条件里**没有排除"有判准"**）。
**口径修正（写进 rubric，代码留 P2）**：口号判定必须**同时**满足"无判准 ∧ 无据 ∧ 无例"；不得对辩题核心词单独判罚。即把 `matter` 的条件从 `SLOGAN ∧ ¬EXAMPLE ∧ ¬据` 收紧为 `SLOGAN ∧ ¬EXAMPLE ∧ ¬据 ∧ ¬PRECISION`。

## 3. 抓漏

### 3.1 代码现状（以代码为准，共 5 类）

| 类型 | 埋雷句（原文） | 出现方式 | 判定 |
|---|---|---|---|
| 以偏概全 | 我身边遇到的同学都是这么想的，可见所有人都反对这个方案。 | 追加在 AI 发言**末尾** | 字符串相等 |
| 诉诸权威 | 很多专家都说过这个结论，早就不需要再讨论了。 | 同上 | 同上 |
| 未证前提 | 这一点显然是常识，我方不再赘述。 | 同上 | 同上 |
| 偷换概念 | 对方说要「可执行」，那就等于「必须立刻执行」，二者是一回事。 | 同上 | 同上 |
| 循环论证 | 这个方案是合理的，因为它确实很合理。 | 同上 | 同上 |

- 埋雷概率：`novice 0 / 默认 0.45 / contest 0.75`（`FlawService.java:36-41`）。
- 加分：命中 +3，上限 +9（`ScoreService.java:154`）。**指错不倒扣**（`point()` 只记 `hit=false`）。
- 埋雷句**不做语义适配**：不论辩题、不论席位、不论 AI 人设，都从这 5 句里抽一句接在末尾（`FlawService.java:43-46`）。

### 3.2 与真实反驳训练的 5 处差距

**差距 1：位置永远在句尾 → 练的是校对，不是听漏。**
真实赛场上漏洞藏在论证中段（"因为 A，所以 B"里 A 没证明）。现在的埋雷是"最后补一句错的"，玩家学会的是"看最后一句"。

**差距 2：句池固定 5 句 → 2–3 场就能背。**
5 类 × 1 句，`contest` 难度下 75% 概率出雷，一场 18 步里能遇上 8–10 个雷，全部来自同一批句子。第 3 场开始，识别不需要理解，只需要回忆。

**差距 3：没有"无漏"选项 → 只会答"有漏"，不会答"这条没问题"。**
真实反驳训练里，**判断"这一段站得住"同样是能力**（否则会变成"见到什么都想拆"的杠精）。现在每轮都必有雷（除非不埋），玩家不需要做"这是不是真漏洞"的判断。

**差距 4：判定是字符串匹配，不是"指认到句"。**
`point()` 只接收 `type`（`MatchService.java:411-418`）：玩家选中"诉诸权威"就算对，**不需要指出是哪一句**。所以训练动作缺了最关键的一半——定位。而且 `correct`（正确答案）在响应体里直接回传，任何客户端都能在第一次错误猜测后读到。

**差距 5：可被刷满。**
`point()` 无次数限制、`markFlaw` 覆盖写（`Store.java:253-255`），5 类全试一遍必然命中。配合 +9 上限，抓漏就是"多调 5 次接口拿 9 分"。
**口径建议（文案层可先落）**：抓漏按**首答计分**（first-attempt scoring）；同时把"指错"做成 `−1`（现在注释说"指错了倒扣一点"但代码没实现，`FlawService.java:12-13` 与实现不符，属文案与实现不一致，至少要在文档里改口径）。

### 3.3 补 2 类（类别名 + 判定例句 + 为什么值得抓）

选择标准：**①真实赛场高频；②一句话可判定（不靠语义玄学）；③与现有 5 类不重叠；④规则能抓到特征**。按这个标准补这两类：

#### 补类 1：举证责任倒置（burden_shift）

- **判定例句**：「你没法证明这个政策一定会失败，所以它就是可行的。」／「对方没有拿出数据说明有害，可见无害。」
- **为什么值得抓**：这是新手在真实比赛里**最常被绕进去**的一类——它听起来像在讲道理，实际是把"谁该举证"偷偷调换了。正面主张（"可行/无害"）的举证责任在提出方，不能靠"你证伪不了"来成立。抓到它，一句话就能翻盘：「举证责任在您方，不在我方；您方主张可行，请给出可行性的最低证据。」
- **规则可抓特征**：`(没法|无法|不能|没有)证明/证据` + `所以/可见/因此` + 结论；或 `(你|对方).*(证伪|反驳不了)`。
- **该放哪个环节**：质询（"答"）、自由辩——这两处最常出现"反问式免责"。

#### 补类 2：相关当因果 / 因果倒置（correlation_causation）

- **判定例句**：「装了监控的城市犯罪率都下降了，可见监控降低了犯罪。」（相关当因果）／「因为大家焦虑，所以才会不停比较——你看爱比较的人都很焦虑。」（因果倒置／同语反复）
- **为什么值得抓**：它是"论据看起来有数据、结论却不成立"的主因，也是**论据维与论证维的交叉点**：数据是真的，推理是假的。抓到它，训练就从"查资料"升级到"查推理"。而且它与现有 5 类都不重叠（诉诸权威讲来源、未证前提讲缺前提、以偏概全讲样本）。
- **规则可抓特征**：`都/同时/越……越……` + `所以/说明/可见`（伴随→因果）；或 `因为 A 所以 B` 且 A、B 互为定义（"因为焦虑所以焦虑"）。
- **该放哪个环节**：驳立论、总结（数据类论证集中地）。

#### 为什么不再补第三、第四类

| 候选 | 不补的理由 |
|---|---|
| 滑坡（slippery slope） | 与「未证前提」高度重叠：滑坡的实质是"每一环都没证明"，判定上无法与前者稳定区分，会造成标注争议 |
| 人身攻击 / 诉诸情感 | AI 对手人设不会用（四家人设都在打论点），加了也出不来；真实训练价值低于上两类 |
| 虚假两难 | 判定需要理解"是否还有第三选项"，规则抓不准，只能人工判 → 放 P2，与"人工复核"绑定 |

**补完后的 7 类口径表**（写进 rubric-v3 的 `flawTypes`）：

| key | 名称 | 判定例句（最短版） | 规则特征 | 典型环节 |
|---|---|---|---|---|
| hasty_generalization | 以偏概全 | 我身边的同学都这样，可见所有人都这样。 | 个体样本 + "所有/都" | 立论、驳立论 |
| appeal_to_authority | 诉诸权威 | 专家都这么说，不需要再讨论。 | "专家/权威/大家都" + 无需论证 | 立论、总结 |
| unproven_premise | 未证前提 | 这一点显然是常识，不再赘述。 | "显然/众所周知/毋庸置疑" | 全环节 |
| equivocation | 偷换概念 | 可执行就等于必须立刻执行。 | "就是/等于/一回事" + 两个不同词 | 质询、驳立论 |
| circular_reasoning | 循环论证 | 它合理，因为它确实合理。 | 结论词在理由里复现（子类：同义反复） | 自由辩、总结 |
| **burden_shift** | **举证责任倒置** | 你证明不了它有害，所以它无害。 | 否定举证 + 推出正面结论 | 质询答、自由辩 |
| **correlation_causation** | **相关当因果** | 两件事一起变，可见一个导致了另一个。 | 伴随/共变 + 因果结论 | 驳立论、总结 |

## 4. 弱项专练（drill）设计建议

### 4.1 先从"最低加权维"到 drill 的映射规则（focusRule）

**不要用"最低原始分"选弱项**——那会让"论据 40 分（权重 10）"永远压过"论证 58 分（权重 30）"，专练方向被低权重维度绑架。

正确做法（`focusRule`）：

```
lost(d) = weight(d) × (100 − score(d))      ← 该维度这一场丢掉的"总分份额"
focus   = argmax lost(d)
并列打破：按"可训练性"排序 应变 > 论证 > 立论 > 论据 > 语言
阈值：max lost < 8 → 不生成专练，只出综合复盘（避免为噪声生成练习）
```

举例（实测分布下真实会发生的情况）：某场 `立论 62 / 论证 55 / 应变 44 / 语言 66 / 论据 40`
→ lost = 25×38=950、30×45=1350、25×56=1400、10×34=340、10×60=600
→ `focus = 应变`（1400 最大），而不是"论据最低分"。**这才是"最低加权维"的正确算法**。

### 4.2 三个 drill（触发条件 / 题面 / 验收），对齐 `SPEC.md` §17.2

> 三个 drill 分别对应"应变 / 论证 / 立论"三处最常成为 `focus` 的维度。全部复用 `mode=DRILL` + `POST /api/matches`（`R-DRILL-01`、§17.2 末条），只记 `drill_record`（`R-DRILL-04`），连续 3 轮取最好（`R-DRILL-02`）。

#### D1 · 质询逼问（drill_type = `query_press`）

- **触发条件**：`focus = 应变`，或本场瑕疵含 2 次以上 `未回应对方`，或逐回合 `脱靶` ≥2 次。
- **题面（可直接抄进 UI）**：
  > 「对方刚说完这句：『{对方上一段 80 字，含一个未证前提}』
  > 你的任务：**连发 3 个只能用『是』或『否』回答的问题**，把他逼到一个他不能否认的前提上。
  > 规则：每问 ≤25 字；不许一次问两件事；他若答非所问，你只有一次追问机会——第一句必须是『您没有回答，我问的是……』。」
- **轮次结构**：3 轮，每轮换一个 AI 对手（快攻派 / 定义派 / 归谬派，`JudgePersonas` 之外的八席人设里挑），每轮 = 3 问 + 1 次追问窗口。
- **验收（机器可判）**：
  1. 3 问全部 ≤25 字且含问号（R）；
  2. 3 问中至少 2 问为**封闭问**（含 `是否/有没有/是不是/能不能/难道` 之一）（R）；
  3. 至少 1 处引述对方原话 ≥6 字（复用 `ScoreService.shares`，R）；
  4. 追问轮：对方回答与问题 4-gram 重合 <0.2 时触发，追问须含"您没有回答"（R）；
  5. **通过线**：1–4 全满足，且 AI 被逼出 ≥1 次让步标记（`concession=true`，由 AI 侧在生成时打标）。
- **记录**：`drill_type=query_press`、`hits=[未回应对方, 未证前提]`、`best_of=3` 的分。
- **不合格出口**：3 轮全不通过 → 降级播放一段"示范质询"（3 问范式），再重练，不算失败。

#### D2 · 三句话拆一个论点（drill_type = `rebut_three_lines`）

- **触发条件**：`focus = 论证`，或 `causal=0` 的回合 ≥1，或出现 `SLOGAN` 且无判准。
- **题面**：
  > 「对方给了这个论点：『{对方最强论点，含一处未证前提}』
  > 用**三句话**拆掉它：
  > ① 他的前提是他没证明的（引他的原话）；
  > ② 举一个反例（要具体到人、地、时或制度名）；
  > ③ 说明为什么这不是特例（机制）。」
- **轮次结构**：3 轮，论点难度递增（事实型 → 机制型 → 价值型）。
- **验收（机器可判）**：
  1. 恰为 3 句（按 `。！？` 切分，R）；
  2. 句 ① 含对方原话 ≥6 字（R）；
  3. 句 ② 含 `例如/比如/以……为例` 且含专名（≥2 字非虚词连续串，R）；
  4. 句 ③ 含 `因为/所以/机制/导致`（R）；
  5. 三句合计 ≤120 字（R）；
  6. **不得**出现 `显然/众所周知/毋庸置疑`（与抓漏词表同源，R）；
  7. 通过线：1–6 全满足 + 人工抽检"反例真的反驳了那个前提"。
- **记录**：`drill_type=rebut_three_lines`、`hits=[未证前提, 以偏概全]`。

#### D3 · 判准落地（drill_type = `standard_grounding`）

- **触发条件**：`focus = 立论`，或 `PRECISION` 缺失且 `STANDARD` 缺失（即"有立场没判准"）。
- **题面**：
  > 「给这道题写**一条判准**，必须写成：『只要 X 成立，我方就赢。』
  > 再补两句：X 由**谁**、用**什么**（统计/法规/报告名）可以核查？
  > 最后，用对方的视角写一句：这条判准会让我方**输在哪**？」
- **轮次结构**：3 轮，同一辩题的正/反/中立判准各一次（练"判准不是自利条款"）。
- **验收（机器可判）**：
  1. 含条件句 `只要……就……`（R）；
  2. 含核查主体（`统计局/法院/教育部/世卫/审计/年报` 等名单）**且**含数据源名（R）；
  3. ≤80 字（R）；
  4. 第 4 句（自伤句）必须存在，且含 `输/不利/被反驳`（R）；
  5. 通过线：1–4 全满足 + 人工抽检"这条判准换到对方嘴里也成立"（不自利）。
- **记录**：`drill_type=standard_grounding`、`hits=[未证前提]`。

> **为什么是这三个**：它们分别对应"听不住（应变）、推不通（论证）、立不牢（立论）"三种**不同的失败**，且验收全部可以退化成规则可判的条件——`R-DRILL-03` 要求"每轮独立评分、取最好一次进 drill_record"，若验收靠人判，取最好一次就没有可比性。

### 4.3 与 SPEC §17.2 的逐条对齐

| 条款 | 本文档落点 | 说明 |
|---|---|---|
| `R-DRILL-01` 每条薄弱项挂一个专练入口 | §4.1 `focusRule` + §4.2 触发条件 | 薄弱项 = `lost(d)` 最大者，`drill_type` 由维度唯一确定（应变→D1、论证→D2、立论→D3），论据/语言暂不设 drill（可训练性低） |
| `R-DRILL-02` 连续 ≥3 轮、取最好一次 | 三个 drill 均 3 轮 | 每轮换 AI 对手，避免同一对手同一话术 |
| `R-DRILL-03` `drill_record` 记类型/题/分/命中标签 | 每 drill 的"记录"行 | `hits` 用 §3.3 的 7 类 key，与抓漏同词表 |
| `R-DRILL-04` 不生成完整 `record` | 复用 `mode=DRILL` | 与 §3.4 的 DRILL 模式共用，不新增接口 |
| `R-SCORE-04` 复盘按"扣分权重"排序薄弱项 | §4.1 `lost(d)` | 现有实现若按原始分排序，需按本文档改口径（代码级，P2） |
