# 两人协作规范（思弈阁）

> 场景：你负责辩论主体（赛制/AI/评分），他负责社区板块。
> 目标：两条线各改各的文件，只在**约定好的接口点**合流，避免天天解冲突。

---

## 0. 先看现状：为什么直接写会撞车

| 现状 | 后果 |
|---|---|
| 前端只有一个 `index.html`（1230 行，内联 CSS+JS） | 两个人改同一个文件，每一行都可能冲突 |
| 后端 `Store.java` 一个类装了所有表 | 他加社区表要改你的文件 |
| 没有 git 仓库 | 只能靠"你把 zip 发我"合并，无法回退 |

所以第一步不是分工，是**把社区隔出去**。下面已经隔好了。

## 2. 接口契约（v4.2 冻结版 · 15 个路由 / 14 个接口）

> 本节 2026-11-02 已按 `docs/SPEC.md`（v4.2）§7 重写。旧的 5 接口表（`{total,list}`、`page=0`、
> `{ok,id}`、toggle 点赞）**已作废**。完整字段表 / 错误码 / 容错矩阵见 `docs/社区接口契约.md`。

| # | 方法 · 路径 | 请求 | 返回 | 状态码 |
|---|---|---|---|---|
| 1 | GET `/api/community/posts` | `type? title? topicId? range? sort? page?=1 size?=20` | `{items,total,page,size}` | 200 |
| 2 | GET `/api/community/posts/{id}` | —— | post item + `body`/`updatedAt` | 200 / 404 |
| 3 | POST `/api/community/posts` | `{type,title,body,topicId?}` | `{postId}` | 200 / 400 |
| 4 | PATCH `/api/community/posts/{id}` | `{type?,title?,body?,topicId?}`（null=解绑） | `{postId}` | 200 / 400 / 403 / 404 |
| 5 | DELETE `/api/community/posts/{id}` | —— | 无 body | 204 / 403 / 404 |
| 6 | POST `/api/community/posts/{id}/view` | —— | 无 body | 204（Redis 故障也 204） |
| 7 | GET `/api/community/posts/{id}/comments` | `page?=1 size?=10` | `{items(楼),total(仅楼数),page,size}` | 200 / 404 |
| 8 | GET `/api/community/comments/{rootId}/replies` | `page?=1 size?=20` | `{items,total,page,size}` | 200 / 404 |
| 9 | POST `/api/community/posts/{id}/comments` | `{body, replyObjectType?, replyObjectCommentId?}` | `{commentId}` | 200 / 400 / 404 |
| 10 | DELETE `/api/community/comments/{id}` | —— | 无 body | 204 / 403 / 404 |
| 11 | POST `/api/community/posts/{id}/like` | —— | 无 body（幂等） | 204 / 404 |
| 12 | DELETE `/api/community/posts/{id}/like` | —— | 无 body（幂等） | 204 / 404 |
| 13 | POST `/api/community/comments/{id}/like` | —— | 无 body（幂等） | 204 / 404 |
| 14 | DELETE `/api/community/comments/{id}/like` | —— | 无 body（幂等） | 204 / 404 |

**约定**：
- 路径前缀统一 `/api/community/**`，不和 `/api/matches`、`/api/topics` 混
- 表名统一 `sy_` 前缀：`sy_post` / `sy_post_comment` / `sy_community_like`，只在 `schema-community.sql` 里建
- 列表响应包固定 `{items,total,page,size}`，**无** `pages`/`hasMore`；`page` 从 **1** 起，`size` 夹 1..50
- 时间一律 **epoch 毫秒数字**；后端输出 **camelCase**，前端不再读 snake_case
- 身份走请求头 `X-User-Id`（可选 `X-User-Name`），服务端 `u-demo` 兜底并打 WARN
- 错误体固定 `{"code":"POST_NOT_FOUND","message":"..."}`；**`CONTENT_BLOCKED` 已废弃**，
  命中敏感词照样发布、正文逐码点替换为全角＊（U+FF0A）后落库（R-COM-39）
- 枚举容错保持既有行为：`type` 非法报 400，`sort`/`range` 非法静默降级（不要"顺手统一"）

## 3. Git 分支模型（推荐）

```bash
# ── 一次性初始化（你来跑）──
cd D:\siyige
git add -A
git commit -m "init: 思弈阁主工程 + 社区模块骨架"
git remote add origin https://gitee.com/xxx/siyige.git
git push -u origin main

# ── 他这边 ──
git clone https://gitee.com/xxx/siyige.git
git checkout -b feature/community
# 只改 com/siyige/community/**、schema-community.sql、static/js/views/community.js
git add -A && git commit -m "community: 帖子/评论/点赞"
git push origin feature/community

# ── 你这边合 ──
git fetch origin
git merge origin/feature/community
```

**合并方向永远是：他 → 你**。你不要往他的分支推东西。

### 分支命名（2026-11-03 起实际在用）

| 分支 | 谁用 | 内容 |
|---|---|---|
| `main` | 主 | 对外稳定版，**一个功能一条提交**（squash 合入） |
| `dev-wandou23333` | 社区线 | 集成分支，功能合并到这里联调 |
| `dev-wandou23333-feature-<名>` | 社区线 | 单个功能分支，做完 squash 成 1 条进 dev |

合并链路：`feature-*` →`dev-wandou23333`（压缩为 1 条）→ `main`（快进）。

## 4. 共享文件冲突怎么处理

如果哪天必须改同一个文件（比如都要动 `application.yml`）：

1. **追加，不重写**：只在末尾加自己的配置块，不改别人的行
2. **小数提交**：一次 commit 只做一件事，冲突了好定位
3. **合之前先拉**：`git pull --rebase origin main`，别等攒一周再合

`index.html` / `core.js` / `app.css` 是最大风险点。规矩是（2026-11-03 修订，原为"只有辩论方能改"）：

> **这三个是共享文件：改动前知会；只追加不重写；一次提交只做一件事；
> 功能代码放自己的 view 文件里，这三个文件里只留"接线"的那几行。**
>
> 新页面一律在 `static/js/views/` 下新建 view，只在 `index.html` 加一行 `<script>`、在 `core.js` 的分发表加一行。

## 5. 不用 git 的最低成本做法

如果暂时不想弄仓库：

1. 他只在 `com/siyige/community/`、`schema-community.sql`、`static/js/views/community.js` 三个位置写
2. 写完整目录打包发你
3. 你覆盖这三个位置 → 重新 `mvn package` → 起服务
4. **不要互相发 index.html**

这套能跑，但**没有历史、没法回退**，只适合两周内的短合作。

## 9. Git 卫生（2026-11-03 新增，必须遵守）

| 规则 | 说明 |
|---|---|
| **截图/录屏不入库** | `demo/shots/`、`docs/shots/`、`预览截图/` 已在 `.gitignore`；需要交付截图就放磁盘、单独发，不要 `git add` |
| **构建产物不入库** | `server/target/`、`*.jar`、`*.class` |
| **本地配置不入库** | `application-local.yml`、`server/config/`（含 API Key） |
| **一次提交一件事** | message 用 `type(scope): 说明`，例如 `feat(auth): T2 账号与密码核心` |
| **只 add 自己改的文件** | 用 `git add <具体文件>`，**禁止** `git add -A` |
| **禁止清场式回滚** | **禁止** `git checkout -- .`、`git reset --hard`、`git stash`：会连带清掉别人未提交的改动 |
| **推之前先看 diff** | `git status` + `git diff --stat` 确认没有截图、日志、临时文件混进来 |
