# 两人协作规范（思弈阁）

> 场景：你负责辩论主体（赛制/AI/评分），他负责社区板块。
> 目标：两条线各改各的文件，只在**约定好的接口点**合流，避免天天解冲突。

---

## 0. 先看现状：为什么直接写会撞车

| 现状 | 后果 |
|---|---|
| 前端只有一个 `index.html`（1230 行，内联 CSS+JS） | 两个人改同一个文件，每一行都可能冲突 |
| 后端 `Store.java` 一个类装了所有表 | 他加社区表要改你的文件 |
| 没有 git 仓库 | 只能靠"你把 zip 发我"合并，无法回退 |

所以第一步不是分工，是**把社区隔出去**。下面已经隔好了。

## 2. 接口契约（他按这个写，你按这个测）

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| GET | `/api/community/posts?page=0&size=20` | —— | `{total, list:[{id,title,content,user_name,likes,created_at}]}` |
| POST | `/api/community/posts` | `{title, content, userId, userName, topicId?}` | `{ok, id}` |
| GET | `/api/community/posts/{id}` | —— | `{post, comments:[...]}` |
| POST | `/api/community/posts/{id}/like` | —— | `{ok, likes}` |
| POST | `/api/community/posts/{id}/comments` | `{content, userId, userName}` | `{ok}` |

**约定**：
- 路径前缀统一 `/api/community/**`，不和你现有的 `/api/matches`、`/api/topics` 混
- 表名统一 `sy_` 前缀，但只在 `schema-community.sql` 里建
- 错误统一走已有的 `ApiErrors`（`{code, message}`），他不用另写异常处理

## 3. Git 分支模型（推荐）

```bash
# ── 一次性初始化（你来跑）──
cd D:\siyige
git add -A
git commit -m "init: 思弈阁主工程 + 社区模块骨架"
git remote add origin https://gitee.com/xxx/siyige.git
git push -u origin main

# ── 他这边 ──
git clone https://gitee.com/xxx/siyige.git
git checkout -b feature/community
# 只改 com/siyige/community/**、schema-community.sql、static/community.html
git add -A && git commit -m "community: 帖子/评论/点赞"
git push origin feature/community

# ── 你这边合 ──
git fetch origin
git merge origin/feature/community
```

**合并方向永远是：他 → 你**。你不要往他的分支推东西。

### 分支命名

| 分支 | 谁用 | 内容 |
|---|---|---|
| `main` | 你 | 永远可运行 |
| `feature/community` | 他 | 社区 |
| `feature/<你的功能>` | 你 | 赛制、AI、评分 |

## 4. 共享文件冲突怎么处理

如果哪天必须改同一个文件（比如都要动 `application.yml`）：

1. **追加，不重写**：只在末尾加自己的配置块，不改别人的行
2. **小数提交**：一次 commit 只做一件事，冲突了好定位
3. **合之前先拉**：`git pull --rebase origin main`，别等攒一周再合

`index.html` 是最大风险点。规矩是：

> **只有你能改 `index.html`。** 他需要加页面，就在 `community.html` 里自己写，
> 需要入口就告你，你加一行。

---

## 5. 不用 git 的最低成本做法

如果暂时不想弄仓库：

1. 他只在 `com/siyige/community/`、`schema-community.sql`、`community.html` 三个位置写
2. 写完整目录打包发你
3. 你覆盖这三个位置 → 重新 `mvn package` → 起服务
4. **不要互相发 index.html**

这套能跑，但**没有历史、没法回退**，只适合两周内的短合作。

### 全局约定（改之前必须知道）

- core.js 里的 S 是全局状态，任何 view 都能读写，但**只有 core 能定义新字段**
- 每个 view 文件只导出**一个渲染函数**（iewXxx()），返回 HTML 字符串
- 渲染后需要挂事件的，用 onclick="fn()"，n 必须是全局函数
- 不要在一个 view 里改另一个 view 的 DOM
