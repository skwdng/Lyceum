# 思弈阁 视觉与交互规范 v1

> 适用范围：`web/src/**`（Vue 3 前端）。样式入口仍是 `style.css`（全局变量与外壳）、
> `debate.css`（对局/复盘）、`community.css`（社区）、`video.css`（短视频）。
> 本规范**不引入新配色**：所有颜色都能在 `web/src/style.css` 的 `:root` 或现有规则里找到出处；
> token 文件 `web/src/assets/tokens.css` 是这些值的唯一引用入口。
>
> 视觉稿：`docs/mockups/复盘页-口径面板.html`（静态、双击即开、内联 CSS 无外链）。

---

## 0. 三条总原则

1. **先结论，后证据，再动作。** 用户打开任何一页，第一眼必须能读到「我这场的结论是什么」；
   想深入再往下看证据；最后才是「下一步做什么」。任何把过程细节放在结论前面的排版都算错。
2. **新代码不写字面色值。** 只写 `var(--token)`。评审时看到 `#` 开头的十六进制色值出现在
   新组件里，直接打回（`tokens.css` 自身与历史文件除外）。
3. **手机不是缩小版桌面。** 375px 下不允许横向滚动；表格必须降级成卡片；可点区域一律 ≥44px。

## 2. Token 一览（实现：`web/src/assets/tokens.css`）

```
底色/面板   --bg --panel --panel-2 --panel-3 --panel-hover --panel-on
描边        --line --line-soft --line-strong
控件        --track
文字        --text --text-2 --muted --muted-3 --text-inverse --text-on-dark
主色        --accent --accent-weak --accent-line --accent-hover --accent-ring
语义        --ok --ok-weak --ok-ink / --warn --warn-weak --warn-ink / --danger --danger-weak
裁判视角    --judge-1..4
圆角        --radius-sm|md|lg|xl|pill
间距        --space-1..6
字体        --font-sans --font-mono --fs-12|13|14|16|20|28 --lh-tight|body|loose
动效        --dur-1..4 --ease-standard|out|pop|in-out
阴影        --shadow-1|2|accent|3|modal|toast
布局        --sb-w --stage-side --g2-side --content-max --tap-min --focus-w --focus-offset
层级        --z-sticky|mask|drawer|pop|toast
```

**兼容约定**：与旧变量重名的（`--bg`、`--accent` 与 `--bg`、`--blue` 同值）在
`tokens.css` 里取值完全一致，加载顺序不影响渲染；旧名（`--ink/--sub/--line/--card/--blue*`）
**保留不动**，不批量替换，避免一次改动波及全部页面。

## 3. 色彩

### 3.1 主色与语义色

| Token | 值 | 出处 | 用途 |
|---|---|---|---|
| `--accent` | `#2f5bea` | `--blue` | 主按钮、链接、选中态、进度条、总分数字 |
| `--accent-weak` | `#edf1fe` | `--blue-w` | 选中底、标签底、提示条底 |
| `--accent-line` | `#b9c9f7` | `.sp.me` 描边 | 选中描边 |
| `--accent-hover` | `#244bcf` | `.btn.primary:hover` | 主按钮 hover |
| `--ok` | `#0e9f6e` | `--grn` | 加分、达成、成功 |
| `--warn` | `#c2671e` | `--org` | 提醒、扣分预警、漏洞标签 |
| `--danger` | `#c0392b` | `--red` | 错误、问题、失败 |

语义色一律**三档成组**：实色（图形/填充）+ 弱底（容器）+ `-ink`（文字）。
文字档必须是 `-ink`，不要拿实色当 12px 正文（`--ok` 白底仅 3.39:1）。

### 3.2 对比度实测（WCAG 2.1，正文要求 ≥4.5:1）

| 前景 | 白底 `#fff` | `--bg` `#f6f4ef` | 弱底 | 结论 |
|---|---|---|---|---|
| `--text` `#1a1d24` | 16.9:1 | 15.4:1 | — | ✅ |
| `--text-2` `#4a5568` | 7.5:1 | 6.9:1 | — | ✅ 正文次要色首选 |
| `--muted` `#6b7280` | 4.90:1 | **4.46:1** | — | ⚠️ 白底可用；`--bg` 上做正文改用 `--text-2` |
| `--muted-3` `#8a909c` | **3.13:1** | 2.9:1 | — | ⚠️ 仅 ≥14px 或非正文（脚注图标、时间戳） |
| `--accent` `#2f5bea` | 5.52:1 | 5.03:1 | 4.88:1（弱底） | ✅ |
| `--ok` `#0e9f6e` | **3.39:1** | 3.2:1 | 3.09:1 | ❌ 文字改用 `--ok-ink` |
| `--ok-ink` `#087a52` | 5.36:1 | 5.0:1 | 4.89:1 | ✅ |
| `--warn` `#c2671e` | **3.97:1** | 3.7:1 | 3.55:1 | ❌ 文字改用 `--warn-ink` |
| `--warn-ink` `#a85212` | 5.41:1 | 5.1:1 | 4.84:1 | ✅ |
| `--danger` `#c0392b` | 5.44:1 | 5.1:1 | 4.75:1 | ✅ |
| `--line-strong` `#8a909c`（输入框边框） | 3.13:1 | — | — | ✅ 满足 1.4.11 非文本 3:1 |
| `--line` `#e6e3dc`（卡片分隔线） | 1.24:1 | — | — | 只做装饰性分隔线，**不得**作为输入框唯一边界 |

`--ok-ink` / `--warn-ink` 是唯一两个派生值：同一色相（绿 ~159°、橙 ~26°）加深一档，
专为 12–13px 文字达到 AA。它们不是新颜色。

### 3.3 已知技术债（不在本次修复范围，但新代码不许继续加）

| 现象 | 位置 | 处置 |
|---|---|---|
| 三套蓝并存：`#2f5bea` / `#3a63ff` / `#165dff` | `style.css` / `ReviewView.vue` `PANEL_COLORS` / `community.css` | 新代码只用 `--accent`；`#3a63ff` 收进 `--judge-1` 仅作裁判色；社区那套等社区线单独收敛 |
| 11.5px / 10.5px 小字大量存在 | `.tag` `.dim` `.st` `.cm-*` | 新代码最小 12px（§4） |
| `#8a909c` `#a8adb8` 当正文色 | 复盘页说明文字、`.empty` | 新代码改 `--muted` |

**颜色不许单独承载信息**：抓漏 `3/5` 不能只靠绿/红区分，必须带文字（`抓对 3 / 共 5`）或图标。

## 5. 间距

全部是 4 的倍数：`--space-1` 4 / `--space-2` 8 / `--space-3` 12 / `--space-4` 16 / `--space-5` 24 / `--space-6` 32。

用法约定：

| 场景 | 取值 |
|---|---|
| 图标与文字、chip 内边距 | `--space-1` (4) |
| 行内元素之间、标签组 gap | `--space-2` (8) |
| 卡片内小标题与内容、表单项之间 | `--space-3` (12) |
| 卡片 padding、栅格 gap | `--space-4` (16) |
| 区块之间（卡片与卡片） | `--space-5` (24) |
| 页面上下留白、大区块分隔 | `--space-6` (32) |

现有散值（`2/6/7/9/10/11/13/14/18/22/28`）按「就近取 4 的倍数」归并：
`6/7→8`、`9/10/11→8 或 12`、`13/14→12 或 16`、`18→16`、`22→24`、`28→24 或 32`。
只有 1px 描边、`2px` 的 micro gap（标签与计数）允许不落在阶梯上。

## 6. 圆角

| Token | 值 | 用途 | 现有对应 |
|---|---|---|---|
| `--radius-sm` | 6px | 标签、chip、小徽章、小按钮 | `.tag 5px`、`.btn.sm 7px`、`.seat .k` |
| `--radius-md` | 9px | 按钮、输入框、行 hover 块 | `.btn 9px`、`.inp 9px`、`.auth-field input 9px` |
| `--radius-lg` | 12px | 卡片、聊天区、席位条、表外框 | `.card 12px`、`.chat 12px`、`.strip 12px` |
| `--radius-xl` | 16px | 弹层、抽屉 | `.panel 16px`（`.cm-modal 14px` 归并） |
| `--radius-pill` | 999px | 胶囊按钮、钱包 chip | `.preset 20px`、`.wchip 20px` |

同级元素圆角必须一致：卡片内嵌套的小块用上一级（`lg` 内的块用 `md`），不出现「12px 里套 14px」。

## 7. 动效

| Token | 值 | 用途 |
|---|---|---|
| `--dur-1` | 150ms | hover、颜色/描边过渡（现有 `.15s`） |
| `--dur-2` | 200ms | 气泡进场、展开收起（现有 `.2s`、`.16s`） |
| `--dur-3` | 240ms | 卡片位移、抽屉滑入 |
| `--dur-4` | 320ms | 弹层进场、骨架 ↔ 内容切换 |
| `--ease-standard` | `ease` | 默认（现有全局值） |
| `--ease-out` | `cubic-bezier(.2,.9,.3,1)` | 展开、位移 |
| `--ease-pop` | `cubic-bezier(.2,.9,.3,1.2)` | 弹层（现有 `cmpop`） |

规则：

- **进场**用 `--ease-out`，**出场**用 `--ease-standard`，超过 `--dur-3` 的只允许模态类元素。
- 位移幅度 2–4px（现有 `.msg` 进场 4px、`.topic:hover` -2px），不做大幅滑动。
- 不用无限循环动画做装饰；骨架屏的 shimmer 是唯一例外，且必须在 `prefers-reduced-motion`
  下退化为静态灰块。
- 状态变化不能只靠动画表达：抓漏得分、分数写入这类结果必须有静态可见的终态。

| Token | 值 | 用途 |

## 9. 信息层级

### 9.1 复盘页（`ReviewView.vue`）：结论 → 证据 → 动作

自上而下固定五段，**顺序不可交换**：

| # | 区块 | 层级 | 内容 | 视觉权重 |
|---|---|---|---|---|
| 1 | 页头 | 结论锚点 | `本场复盘` + 一句副标题：辩题 · 我占的席位 · 发言次数 · 超时次数 | `--fs-20` 标题 + `--fs-12 --muted` 副标题 |
| 2 | 总分卡 | **结论** | 总分（`--fs-48` `--accent`）+ 「五维加权 · 已写入记录」+ 五维横向条 + 本场检出标签 | 最高，唯一使用 48px 的地方 |
| 3 | 本场最该改的一件事 | **动作（前置）** | 一个维度名 + 当前分 + 一句「你要改什么」+ 一句为什么 + 原话摘录 + 主按钮「看改写建议」 | 次高：`--accent-weak` 底 + 3px 左描边 `--accent` |
| 4 | 评分口径表 | **证据** | 五维 × {分数 / 权重 / 命中依据 / 原话证据}，表尾注明口径版本与权重合计 | 中性白卡，`--fs-13`；**可收起**：收起时标题行必须仍显示「口径版本 + 权重合计」 |
| 5 | 优先改进建议 | **动作（展开）** | 按影响排序的 2–3 条：原话 → 改成 → 预计影响 | 白卡，每条左侧序号 chip |

执行细节：

- 「最该改的一件事」放在第 3 位而不是最底部：多数用户看完成绩就走，**必须让他在第一屏
  就带走一个可执行动作**（375×667 首屏可见：页头 + 总分 + 该改的一件事的标题与首句）。
- 结论区（第 2、3 位）合计高度不超过首屏的 60%，超出就把五维条改成两列。
- 证据一律用**用户原话**（`r.quote`），不写「你论证不足」这类无指代的评价。
- 一条建议只对应一个可执行动作；「注意逻辑严密性」不算动作，「把『所有人都这么认为』
  换成具体数据或删掉」才算。
- 分数低不用红色（`--danger` 只给「错误/异常」），低分是信息不是报错——沿用现有
  `.score-color` 用主色的决策。

### 9.2 对局页（`MatchView.vue`）：当前态势 → 我的操作 → 辅助设置

| 层级 | 区块 | 规则 |
|---|---|---|
| 1 态势 | 席位条 `.strip` + 赛制进度 `.steps` | 永远在顶部：我在哪个席位、现在谁发言、还剩几步。当前席位必须同时有描边和文字（`.sp.cur` 的 inset 环 + `当前` 文案） |
| 2 主区 | 发言流 `.chat` | 阅读区最大，气泡 `--fs-14` 行高 1.65；系统提示 `.sys` 颜色比正文浅一档，不抢焦点 |
| 3 操作 | 输入区 `.composer` | 贴在主区底部（现有 `flex` 方案保留，不写死高度）；主按钮唯一且全宽在手机端 |
| 4 辅助 | 材料卡、漏洞卡、催一下 | 收起态默认折叠，不占首屏 |

对局页禁止：在发言流里插入评分/点评（评分只属于复盘，否则打断辩论节奏）。

### 9.3 通用

- 一屏只有一个「主按钮」视觉强度（实色 `--accent`），其余是 ghost。
- 标题与它解释的内容距离 ≤ `--space-2`；两块不同内容间距 ≥ `--space-5`。
- 数字用 `--font-mono`（分数、次数、权重、耗时），文字用 `--font-sans`。

### 9.4 复盘页展开/收起约定

「评分口径」属证据层，允许收起，但必须满足：

1. 收起时标题行常显三样东西：**口径版本**、**权重合计**、**展开/收起提示**（任一缺失都算错——
   用户看不到「这一屏是按什么口径算的」，总分就变成不可质疑的黑箱）。
2. 展开控件用 `<details>/<summary>` 或 `<button aria-expanded aria-controls>`；
   不能用 `div` + `onclick`，键盘和读屏都要能用。
3. 默认状态：桌面可展开亦可收起（当前实现默认收起，可接受）；**≤768px 默认收起**，避免首屏被长表占满。
4. 后端 `rubric` 字段缺失时降级为「本场五维分数 + 固定权重」并显式说明「口径明细尚未返回」，
   不得只显示分数让用户误以为口径为空。

## 10. 三态：空 / 加载 / 错误

三者是**同一位置的三个状态**，容器尺寸不变，避免切态时页面跳动。

| 状态 | 结构 | 文案规则 | 视觉 |
|---|---|---|---|
| 空态 | 图标/符号（可选）+ 一句主文案 + 一句解释 + 一个出口按钮 | 主文案说「没有什么」，解释句说「为什么 / 怎么才会有」，按钮说「怎么开始」 | `--panel` 底、`--radius-lg`、内边距 `--space-6 --space-5`、居中、`--fs-13 --muted`；按钮 `--radius-md`、高 ≥44px（手机） |
| 加载态 | 骨架块（推荐）或一行文案 | 说明「在等什么、大概多久」；>3s 补一句「仍在处理」 | 骨架块 `--panel-on`、`--radius-sm`、shimmer 1.2s；不用整页转圈 |
| 错误态 | 错误标题 + 原因（人话）+ 重试按钮 + 次要出口 | 不复述后端英文错误码；能重试就给重试 | `--danger-weak` 底 + `--danger-ink` 文字 + `--danger` 左侧 3px 描边；**错误就近显示**（贴在出错区域，不弹 toast） |

文案样例（照抄可用）：

- 空：「本场还没有复盘数据」/「打完一场，这里会给出五维评分和逐回合点评。」/ 按钮「去开一场」
- 加载：「四位裁判正在看你的发言…」/「通常 5–8 秒，可以先去别的页签」
- 错误：「复盘没加载出来」/「网络请求失败，或这一场的记录被清理了。」/ 按钮「重新加载」+ 次要「回到辩论记录」

禁止：

- 用 toast 承载「页面加载失败」——toast 会消失，用户回头看不到原因。
- 空态里放两个以上同等强度的按钮。
- 加载态显示 0 分占位（会被误读成真实成绩，复盘总分未出时必须显示「待出分」）。
- 错误态只显示 `Error: 500`。

## 11. 断点与移动端

| 断点 | 名称 | 变化 |
|---|---|---|
| `≥861px` | 桌面 | 侧栏 196px 常驻；`.stage` 两栏 `1fr 288px`；`.g2` 两栏 `1fr 320px` |
| `768px` | 平板 / 手机横屏 | 侧栏变底栏（沿用现有 `≤860px` 规则）；对局舞台单列；两栏内容改单列；口径表保留表格但**去掉「原话证据」列**，改为该行下方折行块 |
| `375px` | 手机竖屏 | 单列；口径表**降级为卡片列表**（每维一张：维度名 + 分数 / 权重 / 依据 / 原话）；按钮全宽；数字 28px 不再加粗到 800 以免爆宽 |

移动端硬规则：

1. **不允许横向滚动**：`body` 不出现 `scrollWidth > clientWidth`；长单词/URL 用
   `overflow-wrap: anywhere`；数据表一律降级，不做横向滚动表格。
2. **触控 ≥44×44px**：所有可点元素（按钮、标签、行、图标按钮、`.seat`、`.preset`）的有效
   命中区最小边 44px；视觉上可以小，用 `padding` 补足，禁用「视觉 28px + 无 padding」。
3. **主按钮在拇指区**（屏幕下 1/3），从不在顶部放唯一主操作。
4. 安全区：底部固定条留 `env(safe-area-inset-bottom)`。
5. 字号不因小屏缩小（用 `--fs-*`），靠换行和折行适配。

## 13. 落地方式与验收

### 13.1 接入（下一步由前端执行，本迭代只新增文件）

```js
// web/src/main.js —— 放在 style.css 之前，让变量先就位
import './assets/tokens.css';
import './style.css';
```

未接线前 `tokens.css` 不产生任何视觉变化（与 `style.css` 同值）。

### 13.2 颜色/字号改写顺序（避免一次性大改）

1. 新增组件与新页面：直接只用 token。
2. 复盘页（`ReviewView.vue`）：与「评分口径面板」一起改，逐块替换，一次一块。
3. 其它页面：只在正好要改该组件时顺手替换，不做全局搜索替换。

### 13.3 提交前自检（8 条）

- [ ] 新代码里没有字面色值（`#` + 6 位十六进制）和魔法字号（非 12/13/14/16/20/28）。
- [ ] 间距是 4 的倍数；圆角只用 sm/md/lg/xl/pill。
- [ ] 375px 下无横向滚动；所有可点区域 ≥44px。
- [ ] 空/加载/错误三态都实现，且加载态不显示 0 分。
- [ ] Tab 键能走完主要操作，focus 轮廓可见。
- [ ] 颜色之外还有文字/图标表达状态。
- [ ] 语义色文字用的是 `-ink` 档（`--ok-ink` / `--warn-ink` / `--danger`）。
- [ ] 动效 ≤ `--dur-3`（模态除外），并已在 reduced-motion 下检查。
