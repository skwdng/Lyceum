## 提示词 A：压测脚本与报告

```
读 AGENTS.md。本次做压测，目标是拿到三个可以写进报告的实测数据。

【任务】
1. 用 k6 写压测脚本（放 docs/k6/），三个场景：
   a) sse-connect.js：并发建立 N 路 SSE 连接，持续 60 秒，统计连接成功率、连接保持时长
   b) sse-throughput.js：恒定 50 路并发，每路发起 3 轮对辩，统计 TTFT 的 P50/P95/P99
   c) api-mix.js：模拟真实用户混合请求（列表 60% / 详情 20% / 登录 10% / 提交发言 10%）
2. 脚本要求：
   - 用 k6 的 http.batch 或 metrics 自定义指标记录 TTFT
   - 参数化：BASE_URL、TOKEN、CONCURRENCY 从环境变量读
   - 每个场景跑 3 档并发：100 / 300 / 500
3. 输出 docs/压测报告.md，包含：
   - 测试环境（CPU/内存/带宽/模型并发上限）
   - 三档并发的：连接成功率、TTFT P50/P95、错误率、CPU/内存峰值
   - 一张"并发数 vs TTFT"的表格
   - 瓶颈分析与结论（明确写出"瓶颈在模型配额而非服务端"这类判断）

【对比实验（重要，报告里单独一节）】
把 spring.threads.virtual.enabled 分别设为 true / false，各跑一次 300 并发，
记录线程数、内存占用、连接成功率，做成对比表。

【要求】
- 不要伪造数据；跑不出来的项标注"未测"
- 给出跑压测的完整命令序列
```

## 提示词 B：生产部署（Docker Compose + Nginx）

```
继续阶段 6。本次做一键部署。

【任务】
1. 补全 docker-compose.yml：mysql + redis + app + nginx 四个服务
   - app 用多阶段 Dockerfile（maven:3.9-eclipse-temurin-21 构建 → eclipse-temurin:21-jre 运行）
   - app 通过 depends_on + healthcheck 等 mysql/redis 就绪
   - 全部连接信息走环境变量，提供 .env.example
   - 不要在生产镜像里塞 maven 和源码（多阶段必须真的分阶段）

2. nginx.conf（SSE 的关键在这几行，逐行加注释说明为什么）
   location /api/debate/ {
       proxy_pass http://app:8080;
       proxy_http_version 1.1;
       proxy_set_header Connection '';
       proxy_buffering off;              # 必须关：否则前端一次性收到全文
       proxy_cache off;
       proxy_read_timeout 3600s;         # 必须调：默认 60s 会掐断长连接
       chunked_transfer_encoding on;
   }
   同时对其他 /api/ 走常规反代；前端 dist 静态托管
   注意 worker_connections 要调大（默认 512，每路 SSE 占 2 个连接）

3. docs/部署手册.md：
   - 服务器要求（2C4G 起步）
   - 从零到可访问的完整命令
   - 常见故障排查表（含 SSE 变成一次性输出、502、连接数打满三种）
4. 一个 scripts/deploy.sh（拉代码 → 构建 → 滚动重启），和一个 scripts/rollback.sh

【禁止】
- 禁止把 API Key、数据库密码写进 docker-compose.yml 明文（用 env_file）
- 禁止用 latest 标签
```

## 验收清单

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 一键部署 | 新机器上 `docker compose up -d` 后 5 分钟内可访问 |
| 2 | SSE 穿透 | 经过 Nginx 后仍是逐字输出（这是最容易回归的问题） |
| 3 | 压测数据 | 有 3 档并发 × 3 个指标的完整表格 |
| 4 | 虚拟线程对比 | 有 true/false 对照数据 |
| 5 | 故障演练 | 手动 `docker stop redis`，应用返回友好错误而不是 500 堆栈 |
| 6 | 结题报告 | 8000 字以上，图不少于 6 张 |

## 结题前最后检查（血泪清单）

1. **演示前重跑一次全链路**：模型配额可能当天被限流，提前确认额度。
2. **准备 PPT 的离线版**：现场网络不可靠，演示视频必须有本地备份。
3. **把 `.env` 从 Git 里排除**：`git log -p | findstr sk-` 检查有没有泄露过 Key。
4. **/actuator 端点别对外暴露**：只保留 health，其余 `management.endpoints.web.exposure.include=health,metrics`。
