## 提示词 C：对辩页 —— 流式渲染（本项目最难的一段）

```
继续阶段 5。本次做对辩页，重点是流式渲染。这里有一个必须解决的性能问题，务必按下面方式实现。

【背景问题】
原型是"状态变化 → 全量 innerHTML 替换"的渲染方式。接入流式后，50 token/秒 × 每次重建 6000 字符 DOM
会让主线程 100% 占用，导致输入框失焦、滚动跳动、动画重置。
在 Vue 里必须用"增量更新"，即：只有正在流式的那个气泡的内容变化，其他 DOM 不动。

【任务】
1. views/DebateView.vue 布局（对照原型）：
   - 左：消息流区域（顶部固定辩题条、消息气泡、底部固定输入框）
   - 右：实时数据面板（当前轮次、平均得分、评分趋势小图、本场提示）

2. 数据结构（stores/debate.ts）：
   messages: Array<{
     id: string, role: 'USER'|'AI', roundNo: number,
     content: string,            // 流式过程中持续追加
     streaming: boolean,
     score?: RoundScore
   }>
   关键：流式时只 mutate 最后一条 message 的 content，不要替换整个数组

3. SSE 客户端（utils/sse.ts）：
   - 用 @microsoft/fetch-event-source（原生 EventSource 不能带 Authorization 头、不能 POST）
   - 封装：postStream(url, body, { onDelta, onScore, onDone, onError })
   - 必须支持 AbortController 中断（用户切页或点"打断"时）
   - 断线重试：最多 2 次，退避 1s/3s，重试时带上已收到内容的长度（可选，先不做续传）

4. 流式渲染优化（硬性要求）：
   - 用 rAF 合并：把收到的 delta 先 push 进 buffer，requestAnimationFrame 里一次性 append 到 content
     （提示：每个 chunk 直接改 ref 会触发 50 次/秒的组件更新，必须批量合并）
   - 消息列表用 key 稳定的 v-for，不要在流式时改动整个数组引用
   - 流式结束后再触发一次评分卡渲染（不要每个 token 都重算评分卡）
   - 自动滚到底部：只在"用户本来就在底部"时才滚动（判断 scrollTop + clientHeight >= scrollHeight - 50）

5. 交互细节：
   - 输入框支持 Shift+Enter 换行、Enter 发送；发送后清空并禁用直到流结束
   - 打分卡在评分事件到达后淡入（transition 200ms）
   - 顶部有"认输/结束并生成复盘"按钮，调 finish 接口后跳 /report/{sessionId}

【禁止】
- 禁止用 v-html 渲染 AI 输出（XSS 风险，且无法增量更新）
- 禁止在 onDelta 里调用任何会触发全列表重排的操作
- 禁止把整个 messages 数组做深拷贝（流式 50 次/秒会 GC 抖动）

【完成后输出】改动清单 + 说明你如何验证"只有目标气泡在更新"（例如用 Vue DevTools 看组件更新范围）
```

## 验收清单

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 构建 | `npm run build` 无 TS 错误，产物 < 1MB（gzip 后） |
| 2 | 登录链路 | 注册 → 登录 → 刷新页面仍保持登录（token 持久化） |
| 3 | 流式 | 文字逐字出现，输入框不失焦，滚动不跳 |
| 4 | 性能 | 流式期间 Chrome Performance 面板无长任务（>50ms）堆积 |
| 5 | 中断 | 流式时点"打断"，请求被 abort，服务端停止生成 |
| 6 | 401 | 手动删掉 localStorage 的 token，访问任意页跳回登录 |
| 7 | 视觉 | 与原型截图逐页对比，色值/圆角/间距一致 |

## 前端改造的三个陷阱

1. **直接搬原型的 `innerHTML` 思路到 Vue**：会用 `v-html` 整块替换，流式时全页闪烁。必须组件化 + 局部更新。
2. **用原生 `EventSource`**：会发现"必须带 JWT"和"必须是 POST"两个需求都满足不了。用 `fetch-event-source`。
3. **每个 delta 都改 ref**：Vue 的响应式会每次都调度更新。必须 rAF 批量。
