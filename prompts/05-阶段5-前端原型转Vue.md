# 阶段 5｜前端：原生 JS 分批迁移到 Vue 3 + Vite 6

> 2026-11-09 重写。**旧版本文档写的是 Vue+TS+Arco Design + axios + SSE 逐 token 渲染，
> 与当前项目实际不符，已作废。** 本文档是迁移的唯一口径，改之前先看 `web/README.md`。

---

## 0. 绝对前提（写代码前先背下来）

1. **后端一行都不改**：Java / schema / `application.yml` 全部不动。需要服务端配合的地方，
   一律用前端方案绕开（典型例子：`/siyige/v2/` 目录直访会 404，就改用
   `/siyige/v2/index.html#/`，而不是去后端加 welcome page）。
2. **分批迁移**，每批结束必须「新页面可用 + 旧页面仍可用」，任何时候都能停。
3. 旧代码在新页面验收通过前**不许删**。
4. 旧前端对应文件是 `server/src/main/resources/static/**`；新前端在 `web/`，
   构建产物提交到 `server/src/main/resources/static/v2/`（服务器上不装 node）。
5. 提交前给 `git diff --stat` + 关键文件 diff，等人确认再提交。
   禁止 `git add -A` / `git checkout -- .` / `git reset --hard`。

## 1. 技术选型（固定，不许换）

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Vue 3 组合式 API + `<script setup>`，**纯 JS 不用 TS** | 与团队现有代码一致，迁移期少一层类型摩擦 |
| 构建 | **Vite 6** | 快；`base: './'` 相对路径让同一份产物在本地 `/v2/` 与线上 `/siyige/v2/` 都能开 |
| 路由 | vue-router 4，**必须 `createWebHashHistory`** | Spring 没有 SPA fallback，history 模式一刷新就 404 |
| 状态 | Pinia（**只放跨页面共享状态**，页面内状态用组件 `ref`） | 避免把旧版 `S` 那个 40 多字段的大对象照搬过来 |
| 样式 | 沿用旧 `css/app.css` 的变量与类名风格，新页面自己写组件样式 | 不引 UI 库，视觉与旧页一致 |
| UI 库 | **不引**（Arco / Element 一律不用） | 体积与风格统一 |

|---|---|
| 旧前端 | `http://host:8787/siyige/` |
| 新前端 | `http://host:8787/siyige/v2/index.html#/` |

全量迁完后（批 4）再把 `/siyige/` 指到 v2、删掉旧文件。

## 3. 三条命令

```bash
cd web && npm i && npm run dev     # ① 开发：http://localhost:5173/#/login（/api /ws 已代理到 8080）
npm run build                      # ② 产物：资源相对路径 ./assets/**（本地与线上通用）
cd ../server && mvn -q -o resources:resources   # ③ 产物验证：直接开 localhost:8080/v2/index.html#/
```

需要强制绝对前缀时才用 `VITE_BASE=/siyige/v2/ npm run build`（默认不用，见 `web/README.md`）。

## 4. 六个必须规避的坑

| # | 坑 | 做法 |
|---|---|---|
| 1 | 资源绝对路径 | 业务代码零绝对路径；`base` 用相对 `./`，避免本地与线上挂载位置不同导致白屏。旧页 17 处 `/js/... /css/...` 就是反面教材 |
| 2 | API 前缀 | 统一走 `src/api.js`，内部按 `pathname.startsWith('/siyige')` 决定前缀，路径写 `/api/**` |
| 3 | 登录态共用 | token 存 `localStorage['sy_jwt']`，与旧页同一个 key，互跳不掉登录 |
| 4 | WebSocket 只能一条 | 新聊天页建连后，旧 `chat-ws.js` 的连接不能存在 → 迁聊天那批要把旧页「消息」入口切走 |
| 5 | 角标轮询只能一份 | 同一份数据只允许一个计时器（现为 `stores/unread.js` 的 45s）；页面组件不许自己 `setInterval` |
| 6 | 换账号串状态 | 每个 store 提供 `reset()`，`auth.logout/login/register` 统一调 `resetAll()`（上一轮真实 bug） |

## 5. 分批与验收

| 批 | 内容 | 完成定义 |
|---|---|---|
| 0 | 骨架（外壳/路由/请求层/stores）+ 登录 / 注册 / 我的 | 侧栏 15 项（10 链接 + 5 分组）全可点；未迁页回落旧页 |
| 1 | 通知 / 钱包 / 好友 / 热辩榜 / 记录 / 诊断 | 6 页功能等价；角标只有一个轮询 |
| 2 | 聊天（WS）/ 复盘 / 单人 / 多人 / 房间 | 建 WS 后旧聊天入口切走；消息不重不漏 |
| 3 | 社区 / 视频 / 管理台 | 社区深链（帖子/楼层）与旧页一致 |
| 4 | 切入口 + 删旧文件 + 全量回归 | 旧文件删除，`/siyige/` 指向 v2 |

每批的完成定义（缺一不可）：
① 功能等价（对照旧页逐项点一遍，列清单）② 新页面在 `/siyige/v2/` 下可用且不影响旧页
③ `server/scripts/selftest_vue_batch*.mjs` 通过 ④ 提交信息写清「迁了哪些页、行数、遗留问题」
⑤ 报告给「怎么验证」的手动步骤。

## 6. 迁移期路由策略（关键）

已迁移 → 挂真组件；未迁移 → 挂 `<LegacyRedirect>`，它把浏览器送到旧页对应视图
（旧页 `boot()` 支持 `?v=<key>` 深链）。**这样侧栏永远点得通，用户不会撞到空白页。**

`meta.legacy` 的取值必须是旧页认得的键：`solo/room/hotb/diag/records/community/video/chat/friends/notify/me`。

## 提示词 A：批 0（骨架 + 登录）

```
读 web/README.md 与 prompts/05，在 web/ 下完成批 0：
1. 工程骨架：vite.config.js（base=/siyige/v2/、outDir 指到 static/v2、proxy 配 /api 与 /ws）、
   src/{main.js,App.vue,router.js,api.js,nav.js,style.css}
2. api.js：与旧 js/core.js 的 api() 逐条对齐（前缀规则 / sy_jwt / {code,message} 错误体 / 401 清 token）
3. stores：auth（user/token/restore/login/register/logout/rename/changePassword/resetAll）、
   unread（45s 轮询，只允许这一个计时器）
4. 外壳 AppShell.vue：复刻旧 index.html 的侧栏（logo + 四组导航 + 用户卡），未登录时对
   LOGIN_ONLY 页面渲染「登录后可见」引导卡
5. views/LoginView.vue（登录/注册双 Tab）、views/MeView.vue（昵称/改密/退出）
6. router.js：hash 模式；未迁移页面挂 LegacyRedirect
完成后：npm run build:local + mvn resources:resources，跑 selftest_vue_batch0.mjs 全绿再报。
```

## 提示词 C：批 2（聊天，唯一涉及实时通道的一批）

