## 提示词 A：JWT 认证

```
读 AGENTS.md，继续阶段 2。本次只做认证模块。

【任务】实现注册 / 登录 / 当前用户信息三个接口，JWT 无状态认证。

【接口契约】
POST /api/auth/register
  body: { account, password, nickname }
  规则：account 6-32 位；password 6-32 位，BCrypt 存储；nickname 2-12 字
  返回: { userId, nickname, token }

POST /api/auth/login
  body: { account, password }
  返回: { userId, nickname, token, expireAt }
  失败: 账号不存在或密码错误都统一返回 code=40001 msg="账号或密码错误"（不要泄露哪个错）

GET /api/auth/me
  header: Authorization: Bearer <token>
  返回: { userId, account, nickname, avatar, createdAt }

【实现要求】
1. common/util/JwtUtil：基于 java-jwt 4.4.0，HS256，payload 只放 userId + nickname，有效期 7 天，密钥从 ${JWT_SECRET} 读
2. interceptor/JwtInterceptor：解析 token → 放 ThreadLocal<UserContext>；放行 /api/auth/login、/api/auth/register、/api/health、/actuator/**
3. common/context/UserContext：ThreadLocal 持有 userId/nickname，提供 get()/set()/clear()，在 afterCompletion 里必须 clear（否则线程复用会串号）
4. 注册时 account 唯一性：先查再插，并捕获 DuplicateKeyException 兜底（并发下两次请求可能都通过预检查）
5. 密码必须 BCrypt（引 org.mindrot:jbcrypt 0.4），禁止 MD5/SHA1
6. 登录失败计数：同一 account 60 秒内失败 5 次，锁定 5 分钟（Redis key: login:fail:{account}）
7. 参数校验用 jakarta.validation 注解 + @Validated，错误信息中文

【禁止】
- 禁止把密码字段放进任何 VO
- 禁止在日志里打印 token 或密码
- 禁止用 session，必须是 JWT 无状态

【完成后输出】改动清单 + curl 验证命令 + 假设说明
```

## 提示词 B：辩题大厅 + 缓存

```
继续阶段 2，本次做辩题模块。

【任务】辩题列表 / 详情 / 分类筛选 / 关键词搜索，并接入 Caffeine + Redis 两级缓存。

【接口契约】
GET /api/topic/list?category=全部&keyword=&page=1&size=12
  返回: { total, list: [{ id, title, category, difficulty, heat, joinedCount }] }
  规则：category 为"全部"时不过滤；keyword 用 title LIKE 模糊匹配

GET /api/topic/{id}
  返回: { id, title, category, difficulty, heat, proMaterial, conMaterial, joinedCount }

GET /api/topic/categories
  返回: ["全部","科技","社会","教育","价值"]

【缓存要求（这是本阶段的重点）】
1. 列表缓存：key = topic:list:{category}:{keyword}:{page}:{size}，Redis TTL 300 秒
2. 详情缓存：key = topic:detail:{id}，Redis TTL 3600 秒
3. L1 用 Caffeine：maximumSize=200，expireAfterWrite=30 秒，只缓存详情不缓存列表
4. 缓存穿透防护：查不到的 id 缓存空对象（"__NULL__"字符串），TTL 60 秒
5. 缓存击穿防护：详情用 Redis 分布式锁（SETNX，200ms 超时）重建，抢不到锁的线程自旋 3 次后直接查库
6. 写操作（本项目后期有后台改热度）必须删缓存，禁止只更新不删

【实现要求】
- 缓存逻辑封装在 service 里，不要污染 controller
- 用 StringRedisTemplate（不要用 RedisTemplate<String,Object>）存缓存，值用 Jackson 序列化，避免 JDK 序列化导致的反序列化异常
- 列表分页用 MyBatis-Plus 的 Page，返回 PageResult

【禁止】
- 禁止 SELECT *（显式列出字段）
- 禁止把 proMaterial/conMaterial 放进列表 VO（两个字段各 200 字，列表返回会撑大响应体）

【完成后输出】改动清单 + 缓存命中率的验证方法（给出连续两次调用看日志的步骤）
```

## 验收清单

```bash
# 注册
curl -X POST localhost:8080/api/auth/register -H "Content-Type: application/json" \
  -d '{"account":"demo123","password":"123456","nickname":"演示用户"}'

# 登录拿 token
TOKEN=$(curl -s -X POST localhost:8080/api/auth/login -H "Content-Type: application/json" \
  -d '{"account":"demo123","password":"123456"}' | python -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")

# 带 token 访问
curl localhost:8080/api/auth/me -H "Authorization: Bearer $TOKEN"

# 辩题列表
curl "localhost:8080/api/topic/list?category=科技&page=1&size=12" -H "Authorization: Bearer $TOKEN"

# 缓存验证：连续调两次详情，第二次日志应显示 "cache hit"
curl localhost:8080/api/topic/1 -H "Authorization: Bearer $TOKEN"
curl localhost:8080/api/topic/1 -H "Authorization: Bearer $TOKEN"
```

| 检查项 | 通过标准 |
|---|---|
| 密码存储 | 数据库 `t_user.password` 是 `$2a$10$...` 开头 |
| ThreadLocal 清理 | 用同一个线程连续请求两个不同用户，不串号 |
| 越权 | 不带 token 访问 `/api/topic/list` 返回 401 |
| 缓存 | 第二次请求详情日志出现命中标记，且响应时间 < 10ms |
| 缓存穿透 | 请求 `id=99999` 两次，第二次不查库 |

## 这一阶段最容易出的问题

1. **ThreadLocal 泄漏**：拦截器里 `set` 了但 `afterCompletion` 没 `clear`，虚拟线程池复用时会串用户 —— 这是最隐蔽的 bug，必须强制 review。
2. **AI 把 JWT 写成 `session`**：老教程影响，必须纠正。
3. **Caffeine 缓存了 DTO 的引用**：后续修改对象会影响缓存内容，必须缓存不可变对象（`record` 或深拷贝）。
4. **`keyword` 为 null 时拼了 `LIKE '%null%'`**：要在 mapper 层用 `<if test="keyword != null and keyword != ''">`。
